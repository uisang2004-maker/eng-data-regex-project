## 01. 먼저 합의할 한 장

**제품의 중심은 "대신 읽어 주기"가 아니라 "읽는 길 보여 주기"이고, 그 엔진은 정규식이다.** 기능 수보다 **6개 기능이 시연 중 터지지 않는 것**을 우선한다.

| 이번에 확정하는 방향 | 실제로 보여줄 경험 |
|---|---|
| 대상: **영어 논문을 처음 읽는 학부생** | 로그인, 요금, 설치 없이 첫 화면에서 바로 결과가 나온다 |
| 주 입력: **arXiv ID** (+ 텍스트 붙여 넣기) | ID를 넣으면 공식 API로 깨끗한 초록을 불러온다. PDF 복사의 2단 꼬임 문제를 피한다 |
| **원문 3줄 뼈대** | 문제·방법·결과 원문 문장 3개가 뜬다. 근거는 "신호 문구로 찾음" 또는 "위치로 추정"으로 표시한다. 빈 카드가 없다 |
| 약어 → 풀네임 | `RLHF`에 마우스를 올리면 풀네임이 보인다. 부분적으로만 맞으면 "후보"로 표시한다 |
| 추측·확신 (문맥 창) | `may indicate`는 추측, `may be applied`는 표시하지 않는다. 애매하면 "확인 필요"로 표시한다 |
| 영한 나란히 보기 (**켜고 끄기**) + **마스킹 비교** | 켜면 문장이 1:1로 짝지어지고 약어·인용·수치가 보존된다. 마스킹을 끄면 무엇이 망가지는지 비교한다 |
| 근거 규칙 + **읽기 전용 단계 보기** | 하이라이트마다 근거 규칙이 보인다. 미리 준비한 규칙을 켜고 끄며 결과가 바뀌는 모습을 보여 준다(자유 입력 없음) |

**핵심 시연:** arXiv ID를 넣는다 → 원문 3줄 뼈대가 뜬다 → 약어와 추측 표현의 툴팁에서 근거 규칙을 확인한다 → "추측 제외 규칙"을 끄면 `may be applied`가 잘못 칠해지는 모습을 보여 준다 → 번역을 켜고, 마스킹을 껐을 때와 비교한다.

**현재 확보 상태 (2026-11-03 로컬 실행 기준):**
- arXiv cs.CL 초록 300건(CC0, 저자 필드 제외)
- 마스킹 왕복: 2,010문장 불일치 0
- DeepL 실제 번역: 보호 토큰 13/13 보존
- 약어 통과: `GRU`·`YOLO`·`LoRA`·`RAG`·`BERT` / 실패: `BiLSTM`·`XGBoost`·`k-NN`·`CoT`
- 뼈대 문장 신호 문구 검출률(샘플 300건)

| 범주 | 검출률 |
|---|---|
| 방법 | 72% |
| 결과 | 61% |
| 문제 | 29% |
| 문제·방법·결과 셋 다 | **16%** |
| 셋 다 없음 | **15%** |

뼈대 검출률이 낮기 때문에 대체 규칙이 필요하다. 샘플은 대표성이 없다.

**한 줄 차별화:** **AI가 대신 읽어 주는 대신, 정규식이 읽는 길을 보여 주는 논문 도우미.** 번역기 래퍼가 아니라, 번역을 꺼도 동작하는 regex 독해 엔진이다.

## 02. 해결할 문제와 기존 논문 AI의 가치

학생이 영어 논문을 어려워하는 이유는 다섯 가지가 겹친다.
- 약어·전문어
- 요점 찾기
- 주장 강도 판단
- 긴 문장 구조
- 배경지식과 참조 왕복

과학 논문의 약어 비율 증가[R01]와 가독성 하락[R02]도 보고되었다. **이번 범위는 앞의 세 가지(약어, 요점, 주장 강도)에 집중한다.** 긴 문장 구조는 P1이고, 배경지식은 범위 밖이다.

| 기존 자산·관찰 | 우리가 바꿀 전달 방식 |
|---|---|
| Semantic Reader: Goal/Method/Result 하이라이트, 용어 정의 툴팁[R03][R04][R05] | 같은 방향의 표시를 **regex 규칙**으로 하고 근거 규칙을 보여 준다 |
| SciSpace·Explainpaper: LLM이 쉬운 말로 설명[R06] | 설명을 생성하지 않고 원문과 (선택) 번역을 나란히 둔다 |
| 범용 챗봇 "3줄 요약" | 원문에서 고른 **3줄 뼈대**. 지어낸 문장이 없고 근거 등급이 보인다 |
| scite: 바깥 인용의 지지·반박 | **논문 안의** 추측·확신 표현을 문맥 창 규칙으로 칠한다 |

**검증할 변화:**
- 규칙 출력의 정밀도(약어·추측·뼈대)
- 3줄 뼈대 채움률(대체 규칙 전후)
- 마스킹이 번역 훼손을 얼마나 줄이는가

## 03. 입력하면 화면 뒤에서 무엇이 움직일까

| 순서 | 화면 뒤에서 일어나는 일 | 발표자가 설명할 말 |
|---|---|---|
| 1 | arXiv ID → 공식 API로 초록 불러오기 (또는 붙여 넣은 텍스트) | "공식 API라서 텍스트가 깨끗해요." |
| 2 | 기본 정리: 하이픈 개행 복원, 공백 정리 | "끊긴 단어를 이어 붙여요." |
| 3 | 인용·수식을 먼저 마스킹한 뒤 문장 분리 | "`et al.`이나 `Eq. 4`의 마침표에서 끊기지 않게 해요." |
| 4 | 약어 정의 탐색(첫 글자 → 글자 단위), 확신도 판정 | "괄호 안 대문자를 앞 단어와 맞춰요. 덜 맞으면 '후보'라고 표시해요." |
| 5 | 뼈대 판정 → 3줄 선택. 신호 문구가 없으면 위치로 대체 | "신호 문구로 찾고, 없으면 '초록은 문제로 시작해 결과로 끝난다'는 위치 규칙으로 채워요." |
| 6 | 추측·확신 문맥 창 판정 | "`may` 뒤에 무엇이 오는지 보고 나눠요." |
| 7 | (번역 켬) 보호 마스킹 → DeepL → 복원 → 조사 띄어쓰기 정리 | "포장한 토큰은 번역기가 건드리지 못해요." |

**번역기는 문장을 옮기고, 정규식은 읽는 길을 보여 준다.** 번역을 꺼도 1~6단계는 그대로 동작한다.

## 04. 처음 읽는 학생에게는 정보량보다 읽는 순서가 중요하다

**구체적인 화면 배치, 색, 디자인은 이의상 님의 지시를 받아 정한다.** 어떤 디자인이든 아래 기능 원칙은 지킨다.

- 원문을 지우거나 바꾸지 않는다
- 첫 화면에서 **입력 → regex 표시 → 결과**가 바로 보인다(과제 조건)
- 3줄 뼈대 → 세부 표시 순서로 읽기를 안내한다. 빈 카드를 보여 주지 않는다
- 근거 등급("신호 문구로 찾음" / "위치로 추정" / "후보" / "확인 필요")을 텍스트로 보여 준다. 색만으로 전달하지 않는다
- 외부 번역 서비스로 전송된다는 사실을 화면에 안내한다

## 06. 정규식이 결과의 핵심 원인이 되는 곳 (P0)

"확인"은 2026-11-03 프로토타입에서 실행한 결과이고, "신규"는 설계 단계다.

| 범주 | 패턴 요약 | 상태·예 | 일부러 놓치는 경우 |
|---|---|---|---|
| 하이픈 복원 | `(?<=[a-z])-[ \t]*\n[ \t]*(?=[a-z])` → 제거 | 확인 | 원래 하이픈이 있던 단어 |
| 문장 분리 | 인용·수식 선마스킹 + `(?<=[.!?])\s+(?=[A-Z(\["'])` + 예외 약어 목록 | 확인: `i.e.`, `vs.`, `ca.`, `Eq. 4`, `Ref. 12`, `et al.` 정상 | 예외 목록에 없고 대문자가 뒤따르는 약어 |
| 약어 1단계 | 괄호 안 약어 + 단어 첫 글자 맞춤(하이픈 조각 포함) | 확인: `GRU`, `YOLO`, `LoRA`, `RAG`, `BERT` | — |
| 약어 2단계 | 글자 단위 순서 매칭(Schwartz & Hearst 계열[R11]) | 신규: `CoT`, `XGBoost` 대상 | 부분 일치는 "후보"로 표시 |
| 추측 (문맥 창) | 확정: `\b(?:may\|might\|could)\s+(?:\w+ly\s+)?(?:indicate\|suggest\|reflect\|explain\|be\s+due\s+to)\b` / 제외: `\b(?:may\|can\|could)\s+(?:also\s+)?be\s+(?:applied\|used\|extended\|adapted)\b` / 나머지는 "확인 필요" | 단어 목록형 확인, 문맥 창 신규 | 문장을 넘는 문맥 |
| 확신 | `demonstrat(?:e\|es\|ed\|ing)\|significantly\|state[- ]of[- ]the[- ]art…` | 확인 | 통계적 유의성과 강조의 구분 |
| 뼈대 문장 | 신호 문구 4범주(문제·방법·결과·한계) | 확인. 검출률은 §01 표 | 신호 문구 없는 문장 |
| **뼈대 위치 대체** | 신호 문구가 없으면 문제 = 첫 문장, 결과 = 마지막 문장, 방법 = "we/our"가 들어간 첫 문장(없으면 두 번째 문장) | 신규. 채움률을 다시 측정함 | 위치 관습을 따르지 않는 초록(근거 등급 "위치로 추정"으로 표시) |
| 참조·인용 | `\[\d+(?:\s*[,–-]\s*\d+)*\]`, `\(… et al\.,? \d{4}\)`, `Fig\.?\s*\d+` | 확인 | 각주형 인용 |
| 번역 보호 | 약어·참조·수치 → `<x>` | 확인: 13/13 | URL 안 특수문자 일부 |
| 번역 후처리 | 조사 앞 공백 제거(닫힌 조사 목록), "제Section" 제거 | "제" 제거 확인, 조사 신규 | 조사 선택(받침) 오류 |

## 07. 번역은 DeepL, 보호는 정규식 — 번역은 켜고 끄는 층

**번역 엔진은 DeepL API Free로 결정했다(2026-11-03, 이의상 선택). 번역을 꺼도 모든 regex 기능이 동작해야 한다.**

| 확인한 사항 | 근거 |
|---|---|
| 무료 등급 월 500,000자 | 공식 문서[R09] |
| Free 엔드포인트 `api-free.deepl.com`, Free 키는 끝이 `:fx`, `DeepL-Auth-Key` 헤더 | 공식 문서[R08] |
| `tag_handling=xml` + `ignore_tags=x`이면 `<x>` 안의 텍스트를 번역하지 않음 | 공식 문서[R10] |
| 무료 등급에서 보낸 텍스트의 보관·활용 여부 | **미확인**. 화면에 전송 안내를 한다 |

**마스킹 on/off 실측:**
- 초록 30편을 마스킹 켬과 끔으로 각각 번역해 약어·인용·수치의 훼손 비율을 비교한다
- 사용량은 약 4만 자로 월 한도의 약 8%다
- 스크립트 하나로 끝나는 작업이라 P0에 둔다

**말투 혼재**(습니다/한다)는 남은 문제다. 시간이 허락하면 어미 대응표로 통일하고(P1), 아니면 한계로 공개한다.

**운영 원칙:**
- 키는 `.env`에만 둔다
- 시연 예시는 캐시한다
- 무료 한도를 넘는 호출이나 유료 전환은 승인 없이 하지 않는다

## 08. 기능 범위 — 필수 6개, 나머지는 선택

| 등급 | 기능 | 상태 |
|---|---|---|
| **P0-1** | 입력: **arXiv ID 불러오기** + 텍스트 붙여 넣기 + 기본 정리 | 붙여 넣기·정리 있음, ID 입력 신규(수집 코드 재사용) |
| **P0-2** | **원문 3줄 뼈대**(신호 문구 → 위치 대체, 근거 등급 표시) + 뼈대 문장 표시 | 뼈대 있음, 3줄·대체 신규 |
| **P0-3** | 약어 → 풀네임(1·2단계, "후보" 표시)·약어 사전 | 1단계 있음 |
| **P0-4** | 추측·확신(문맥 창 3등급) | 단어 목록형 있음 |
| **P0-5** | 영한 나란히(켜고 끄기) + 마스킹 + **마스킹 on/off 비교·30편 실측** | 번역 모듈 있음 |
| **P0-6** | 근거 규칙 표시 + **읽기 전용 단계 보기 + 준비된 규칙 켜고 끄기** | 규칙 목록만 있음 |
| P1 | 끊어 읽기(고정밀 경계만: `, which`, `;`, 동사 뒤 `that`. 30단어 이상 문장만. **전치사 경계 없음**) | 신규 |
| P1 | 구문 신호(가주어·수동태 꼬리표), 약어 3단계(`BiLSTM`, `k-NN`), 말투 통일 | 수동태 패턴만 있음 |

## 09. 데이터는 합법적인 것만, 샘플은 샘플답게

| 데이터 | 용도 | 출처·권리 | 원칙 |
|---|---|---|---|
| arXiv ID로 불러온 초록 | 시연 주 입력 | arXiv API, 메타데이터 CC0[R07] | 3초에 1회 이하 요청, 저자 필드 제외 |
| 사용자가 붙여 넣는 텍스트 | 시연 보조 입력 | 사용자 본인 | 저장하지 않는다. 번역 시 외부 전송을 안내한다 |
| arXiv 초록 샘플 | 규칙 개발·검수·마스킹 실험 | arXiv API, CC0 | 300건에서 1,000건 이상으로 확대 |
| 직접 작성한 예시문 | 기능 시연 | 팀 작성 | "직접 작성, 실제 논문 아님"을 표시한다 |
| 설문 응답 (시연 후) | 유용성 참고 | 참여 수강생(익명, 동의) | 개인정보를 수집하지 않는다. 집계값만 공개한다 |
| 번역 캐시 | 오프라인 시연, 실험 재현 | 예시문·CC0 초록의 DeepL 결과 | 실제 논문 본문은 커밋하지 않는다 |

## 11. 정확도는 설계가 아니라 결과로 입증한다

아래 숫자는 **사전 목표**이며 현재 실적이 아니다.

| 평가 | 계획과 완료 기준 |
|---|---|
| 규칙 정밀도 (검수형) | 초록 20편에서 규칙 출력을 "맞음/틀림"으로 검수한다(예상 3~4시간). 목표: 약어 0.9 이상, 추측 0.8 이상. 뼈대는 근거 등급별(신호/위치) 정밀도를 보고 |
| 규칙 재현율 (소표본) | 10편에서 약어·추측을 직접 표시해 놓친 비율을 보고 |
| 3줄 뼈대 채움률 | 샘플 전체에서 대체 규칙 전후 비교. 현재 신호 문구만으로 셋 다 채움 16% |
| 마스킹 기여 | 30편 on/off 번역. 보호 토큰 훼손률 비교, on에서 보존율 100% 목표 |
| 문장 분리 | 예외 약어 문장 100개에서 잘못 끊긴 수. 분리 오류가 다른 짝으로 번지지 않음을 테스트로 고정 |
| 유용성 (가벼운 참고) | 시연 후 3문항 익명 설문. 참여자가 5명 이상 모이면 교차 이해 테스트로 확대. **통계적 일반화 불가**를 명시 |

검수는 규칙을 만든 시점과 다른 시점에 하고, 목표에 못 미치면 못 미친 대로 보고한다.

## 13. AI 도구를 쓰는 방식

| 쓰는 곳 | 도구 | 사람이 확인하는 것 |
|---|---|---|
| 기획·문서 초안, 코드 작성 보조 | Claude Code (Anthropic) | 모든 결정과 컨펌은 이의상. 실제로 실행한 테스트 결과만 보고 |
| 번역 (선택 층) | DeepL API Free | 번역 품질은 보증하지 않고, 보호 토큰 보존을 테스트로 확인 |
| 학술 어휘 뜻 초안 (P1) | AI 초안 | 사람이 검수하고 출처를 명시 |

**정규식 규칙의 판단 근거는 사람이 설명할 수 있어야 한다.** AI가 만든 패턴도 테스트와 검수를 통과해야 채택한다.
