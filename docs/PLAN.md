# 프로젝트 계획서 — 처음 읽는 영어 논문 도우미

> 작성 2026-11-03 · 상태: **방향 확정, 범위·일정 컨펌 대기**
> UI·디자인은 이의상 님의 지시를 받아 정한다. 이 문서는 기능, 데이터, 일정만 다룬다.

## 1. 한 줄 정의

**영어 논문을 처음 읽는 학부생**이 텍스트를 붙여 넣으면 원문 옆에 **한국어 번역을 문장 단위로 나란히** 보여 준다. 그리고 정규표현식이 "어디부터 읽어야 하는지, 무엇이 약어이고 무엇이 추측인지"를 표시한다. 결과는 대신 읽어 주는 요약이 아니다. 원문을 그대로 두고 **읽는 법을 알려 주는 표시**이며, 모든 표시에는 근거 규칙이 보인다.

## 2. 왜 이 대상과 이 방향인가

| 근거 | 내용 |
|---|---|
| 시장의 빈틈 | 논문 독해 AI(Semantic Reader, SciSpace 등)는 연구자·석박사 중심이다. 학부생과 일반인은 범용 챗봇 요약에 의존한다(시장 구조를 보고 추론한 것) |
| 평가자 = 사용자 | 상호 평가하는 수강생이 바로 "과제로 영어 논문을 읽는 학부생"이다 |
| 요약의 위험 | 비전문가는 틀린 요약을 알아채지 못한다. 우리는 원문을 유지하고 표시만 하므로, 학생이 직접 판단할 수 있다 |
| 연구 근거 | 과학 논문에서 약어 비율이 늘었다(Barnett & Doubleday 2020). 가독성은 떨어졌다(Plavén-Sigray 외 2017). 우리 샘플 300건에서도 초록당 약어 정의 수가 2012년 0.22에서 2025년 1.04로 늘었다(소량 샘플, 참고용) |

## 3. regex가 핵심인 이유 (번역이 주인공이 되지 않게)

번역은 외부 엔진이 맡는다. 그래서 **regex가 번역 앞뒤를 책임지게** 설계한다.

1. **문장 분리**: `e.g.`, `et al.`, `Fig. 3` 같은 예외를 처리하며 문장을 나눈다. 원문과 번역이 1:1로 짝지어지는 기반이다
2. **번역 보호 마스킹**: 약어, 인용 `[12]`, 그림 참조, 수치, 수식을 번역 전에 `⟦T1⟧` 같은 자리표시자로 바꿨다가 번역 후 되돌린다. 기계 번역이 `BERT`를 음역하거나 `[3, 5]`를 망가뜨리는 것을 막는다
3. **표시 전달**: 영어 문장에 붙은 표시(뼈대, 추측·확신)를 짝지어진 한국어 문장에도 붙인다. 약어와 인용은 자리표시자 덕분에 한국어 쪽에서도 같은 위치에 칠할 수 있다
4. **독해 표시**: 뼈대 문장, 약어→풀네임, 추측·확신, 학술 어휘

발표 메시지: "번역기는 문장을 옮기고, 정규식은 **무엇을 어떻게 읽을지**를 알려 준다."

## 4. 기능 범위

### 필수 (발표 시연에 반드시 들어감)

| # | 기능 | regex 역할 | 현재 상태 |
|---|---|---|---|
| F1 | 텍스트 붙여 넣기와 PDF 복사 잔재 정리(줄바꿈 하이픈, 공백) | 전처리 패턴 | 프로토타입 있음 |
| F2 | **영어·한국어 문장 단위 나란히 보기** | 문장 분리 + 번역 보호 마스킹 | 신규 |
| F3 | 뼈대 문장(문제·방법·결과·한계)과 **추천 읽기 순서** | 신호 문구 패턴 | 프로토타입 있음 (읽기 순서는 신규) |
| F4 | 약어 → 풀네임 툴팁, 약어 사전 | 괄호 정의 + 첫 글자 맞춤 | 프로토타입 있음 |
| F5 | 추측·확신 표시와 **학습 팁**("단정하지 말고 인용하세요") | hedge/booster 패턴, 제외 패턴 | 프로토타입 있음 (팁은 신규) |
| F6 | **학술 어휘 표시 + 한국어 뜻** | 어휘 목록 × 굴절형 패턴(`-s/-ed/-ing/-ies`) | 신규 |
| F7 | 모든 표시에 "어떤 규칙이 잡았는지" 근거 표시, 규칙 목록 화면 | — | 프로토타입 있음 |
| F8 | 샘플 분석 그래프 1~2개(연도별 약어 증가) — 발표 도입용 | 같은 규칙을 대량 적용 | 프로토타입 있음 |

### 선택 (시간이 남으면)

- 문장 난이도(수동태, 명사화, 길이)
- 인용·그림 참조 목록
- arXiv ID를 넣으면 초록을 자동으로 불러오기(공식 API)
- PDF 파일 업로드
- 재사용 허용 라이선스 논문 본문의 분석("약어는 정의되고 몇 문단 뒤에 다시 나오나")

### 하지 않는 것

- 요약 생성
- 배경지식 설명
- 한국어 논문 입력
- 로그인과 사용 기록 저장

## 6. 번역 엔진 (결정 필요)

| 안 | 장점 | 단점·확인할 것 |
|---|---|---|
| **A. DeepL API Free (추천)** | 영한 번역 품질이 좋은 편. 무료 등급이 있다 | 가입·키 발급은 이의상 님이 직접 해야 한다. 무료 한도와 가입 조건은 **확인 필요**. 텍스트가 외부로 전송된다 |
| B. Google Cloud Translation | 안정적 | 무료 한도를 넘으면 유료. 결제 계정이 필요하다 |
| C. 오프라인 오픈소스 번역 모델 | 외부 전송 없음, 무료 | 설치가 무겁고 영한 품질이 낮을 수 있다. 쓸 만한 모델이 있는지 **확인 필요** |

공통 설계:
- 번역 엔진을 갈아 끼울 수 있게 만든다(`translate` 모듈 인터페이스 하나)
- API 키는 `.env`에 둔다(커밋하지 않음)
- 시연 예시는 캐시해서 인터넷이 없어도 동작하게 한다
- 유료 호출은 승인 없이 하지 않는다

## 7. 모듈 구조 (Phase 3)

```
src/
  patterns.py   # 모든 regex + docstring(잡는 것, 예시, 일부러 놓치는 경우)
  collect.py    # arXiv API 수집
  clean.py      # 전처리, 문장 분리
  extract.py    # 약어·뼈대·추측확신·학술어휘·참조 추출
  translate.py  # 마스킹 → 번역 엔진 → 복원, 캐시
  analyze.py    # 연도별 지표, 평가 지표
  visualize.py  # 하이라이트 HTML, 차트
app.py          # Streamlit (UI는 지시 후 결정)
tests/          # 패턴별 양성·음성 테스트, 마스킹 왕복 테스트
```

## 8. 평가 계획 (발표에서 숫자로 말하기 위해)

- arXiv 초록 50편을 직접 라벨링한다. 약어 정의, 뼈대 문장 범주, 추측 표현이 대상이다
- 목표
  - 약어 풀네임 정밀도 0.9 이상
  - 추측 표현 정밀도 0.8 이상
  - 뼈대 문장은 범주별 정밀도와 재현율을 보고한다(목표치는 첫 측정 후 정함)
- 번역 마스킹 테스트: 약어, 인용, 수치가 번역 후에도 100% 보존되는지 확인한다
- 결과는 README와 발표 자료에 그대로 싣는다. 목표에 못 미치면 못 미친 대로 보고한다

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
| 번역이 주인공처럼 보여 regex가 장식이 됨 | 마스킹, 문장 짝짓기, 표시 전달을 시연에서 직접 보여 준다("마스킹 끄기" 비교 등) |
| 번역 API 장애나 한도 초과 | 시연 예시를 캐시해 둔다. 엔진 교체 구조로 만든다 |
| hedge 오탐(`may be applied`) | 제외 패턴과 테스트로 대응하고, 평가 수치를 공개한다 |
| 학술 어휘 목록 라이선스 | 확인되지 않으면 우리 샘플에서 직접 추출한 목록을 쓴다 |
| 한국어 뜻의 오류 | 사람이 검수하고, 출처와 AI 사용 사실을 명시한다 |
| 분야 관습 차이 | 범위를 CS·AI 논문으로 한정하고 한계로 적는다 |
