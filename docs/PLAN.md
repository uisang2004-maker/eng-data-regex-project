# PaperPath — 처음 읽는 영어 논문 도우미

**같은 영어 논문, 처음 읽는 학생에게는 다른 지도.**
영어 논문 PDF(또는 arXiv ID·붙여 넣은 글)를 넣으면 정규표현식이 절을 나누고, 먼저 읽을 문장 3개를 원문에서 고르고, 약어·추측 표현·용어 설명·수치·반복 용어·표/그림 참조를 근거와 함께 표시하는 학부생용 논문 독해 도우미. 옆에서 AI가 문장 단위로 한국어 번역을 붙인다. **읽는 길(무엇을 어디에 표시할지)은 정규표현식이 정하고, AI는 번역과 뜻 풀이만 맡는다(참고용).**

**「영어데이터 처리를 위한 프로그래밍」 기말 프로젝트 | 수강생·평가자용 제안·구조 이해 문서 | 2026.11.05 5차 개정 | 구현 단계(Phase 3), 평가·발표 준비 중**
공개 사이트: https://paperpath-hufs.streamlit.app/ · 실행 코드의 규칙·테스트 기준은 `src/patterns.py`와 `tests/`(`py -I -m pytest` 206 passed, 2026-11-05)를 따른다. 날짜별 진행·실측 기록은 [PROGRESS.md](PROGRESS.md)(1~33번)에 있다.

> **5차 개정 (2026-11-05, 이의상: "네, 개정해")** — 4차 확정안(P0 6개) 이후 11/4~5에 이의상 님 요청으로 들어온 기능과 결정을 본문에 반영했다. 바뀐 원칙은 세 가지다.
> 1. **입력의 중심이 arXiv 초록에서 논문 PDF 전체로 바뀌었다.** 4차까지 "하지 않음"이던 PDF 업로드·2단 편집 복원을 넣었다(절 나누기·앞머리 거르기·표/그림 찾기는 정규식, 글자 위치 읽기는 pdfplumber. AI·OCR 없음).
> 2. **번역 엔진이 DeepL에서 Claude Haiku 5.5(AI 번역)로 바뀌었다.** 키가 없으면 DeepL을 쓴다. 단어 뜻 풀이도 AI가 쓰지만 **어떤 단어를 풀지는 정규식·빈도표가 정한다.** 첫 화면은 이의상 님 결정으로 "AI 번역"을 강조한다.
> 3. **"저장하지 않음" 원칙은 "서버에 저장하지 않음"으로 구체화했다.** 번역·문서는 사용자 브라우저에만 저장하고(다시 열기), 로그인·서버 저장은 하지 않는다.

## 01. 먼저 합의할 한 장

**제품의 중심은 "대신 읽어 주기"가 아니라 "읽는 길 보여 주기"이고, 그 엔진은 정규식이다.** AI는 번역과 뜻 풀이처럼 정규식이 할 수 없는 일만 옆에서 돕고, 모든 AI 결과에는 "참고용"을 붙인다.

| 지금 확정된 방향 | 실제로 보여 주는 경험 |
|---|---|
| 대상: **영어 논문을 처음 읽는 학부생** | 로그인·설치 없이 공개 사이트에서 바로 쓴다 |
| 주 입력: **논문 PDF** (+ arXiv ID, 텍스트 붙여 넣기) | PDF를 끌어다 놓으면 버튼 없이 바로 분석한다. 2단 편집도 왼쪽 단 → 오른쪽 단 순서로 읽고, 저자·이메일·각주·참고문헌은 빼고, **초록 · 본문(절별) · 결론** 쪽으로 나눈다 |
| **원문 3줄 뼈대** | 문제·방법·결과 원문 문장 3개. 신호 문구 강조, 핵심 내용 밑줄, 한국어 이유 한 줄, 카드 아래 번역. 신호 문구로 못 찾으면 "추정"으로 표시한다 |
| 원문 표시 7종 | 약어(풀네임), 추측·가능성, 확신, 참조, 용어 설명(점선 밑줄), 수치 근거, 반복 용어(밑줄 + 뜻 풀이 툴팁) |
| **AI 번역 (Claude Haiku 5.5)** | "번역하기"를 누르면 문장이 1:1로 짝지어지고, 영어 표시(형광펜·밑줄)가 한국어 쪽에도 같은 자리에 옮겨진다. 읽기 모드 4가지(한영 나란히·문장마다 한영·영어만·한국어만) |
| 표·그림을 본문 흐름 속에 | `Table 2`·`Fig. 3`을 **처음 언급한 문장 바로 아래**에 표·그림 카드, 다시 언급한 곳에서는 마우스를 올리면 미리보기 |
| 이해를 돕는 자료 | 논문 흐름도(배경 → 문제 → 방법 → 결과 → 한계), **어려운 단어표**(한국어로 옮겨도 안 풀릴 전문용어만, AI 뜻 풀이 칸), 모델·데이터셋 이름 목록 |
| 근거 규칙 + 읽기 전용 단계 보기 | 모든 표시에 근거 규칙이 보이고, 준비된 규칙을 켜고 끄며 결과가 바뀌는 모습을 보여 준다(자유 입력 없음) |
| 저장 | 번역·문서는 사용자 브라우저에 자동 저장 → 창을 닫았다 와도 "저장된 문서 → 다시 열기"로 API 없이 연다. 다른 PC는 결과 파일로 옮긴다 |

**핵심 시연(3분):** 논문 PDF를 끌어다 놓는다 → 절이 나뉘고 초록의 3줄 뼈대가 뜬다 → 본문 절을 골라 형광펜·밑줄·툴팁(약어 풀네임, 반복 용어 뜻)을 본다 → 처음 언급한 문장 아래의 표를 펼친다 → "번역하기"로 한영 나란히, 한국어 쪽에도 같은 표시가 옮겨진 것을 보여 준다 → 규칙 하나를 끄면 표시가 바뀌는 모습으로 "표시는 정규식이 만든다"를 보여 준다 → 저장된 문서를 다시 열어 API 없이 열리는 것을 보여 준다.

**현재 확보 상태 (실측, 날짜는 PROGRESS 기준):**

| 항목 | 결과 |
|---|---|
| 테스트 | `py -I -m pytest` **206 passed** (11/05) |
| 3줄 뼈대 셋 다 채움 (샘플 300편) | 신호 문구만 60편(20%) → 위치 대체 포함 **221편(74%)** |
| 원문 표시 범위 (300편) | 표시된 단어 비율 14.3% → 용어 설명·수치 추가 18.0% → 반복 용어 추가 25.5% |
| 마스킹 30편 | 보호 토큰 203개 중 그대로 남은 수: 켬 201, 끔 173(차이 30개 중 27개는 표기 변환) |
| 번역문 표시 복원 | 한국어 밑줄 12/12, 형광펜 58/58 (DeepL, 11/04) |
| PDF 시험 7편 | 7편 모두 초록·참고문헌 경계를 찾고 이메일·소속·각주를 본문에서 뺌. 표 57개 중 52개, 그림 43개 중 42개를 영역만 잘라냄 |
| 긴 절 번역 | BERT "3 BERT" 8,807자 63문장: 묶음 3개 동시 전송 21초, 63/63 짝 맞음(Claude, 11/04) |

| 저장·다시 열기 | 같은 PDF를 새로고침 뒤 다시 열 때 번역 사용 0회 |

**한 줄 차별화:** **AI가 대신 읽어 주는 대신, 정규식이 읽는 길을 보여 주고 AI는 옆에서 번역만 돕는 논문 도우미.** 번역을 꺼도 절 나누기·3줄 뼈대·표시·표/그림·단어표는 모두 동작한다.

## 02. 해결할 문제와 기존 논문 AI의 가치

학생이 영어 논문을 어려워하는 이유는 다섯 가지가 겹친다.
- 약어·전문어
- 요점 찾기
- 주장 강도 판단
- 긴 문장 구조
- 배경지식과 참조 왕복(본문 ↔ 표·그림 ↔ 참고문헌)

과학 논문의 약어 비율 증가[R01]와 가독성 하락[R02]도 보고되었다. **약어·전문어, 요점, 주장 강도, 표·그림 참조 왕복**을 다룬다. 긴 문장 구조(끊어 읽기)는 P1이고, 배경지식 설명 생성은 범위 밖이다.

| 기존 자산·관찰 | 우리가 바꿀 전달 방식 |
|---|---|
| Semantic Reader: Goal/Method/Result 하이라이트, 용어 정의 툴팁[R03][R04][R05] | 같은 방향의 표시를 **regex 규칙**으로 하고 근거 규칙을 보여 준다 |
| SciSpace·Explainpaper: LLM이 쉬운 말로 설명[R06] | 설명을 생성하지 않는다. AI는 문장 번역과 고른 단어의 한 줄 뜻만 쓰고 "참고용"으로 표시한다 |
| 범용 챗봇 "3줄 요약" | 원문에서 고른 **3줄 뼈대**. 지어낸 문장이 없고 근거 등급이 보인다 |
| PDF 번역기(통째로 번역) | 절별로 나누고, 원문과 번역을 1:1로 나란히 두고, 원문 표시를 번역 쪽에 옮긴다 |

**검증할 변화:**
- 규칙 출력의 정밀도(약어·추측·뼈대)와 소표본 재현율
- 3줄 뼈대 채움률(대체 규칙 전후, 측정 완료)
- PDF 처리 품질(절 경계, 앞머리 제거, 표·그림 영역)
- 마스킹이 번역 훼손을 얼마나 줄이는가(측정 완료: 효과 작음, 그대로 보고)

## 03. 입력하면 화면 뒤에서 무엇이 움직일까

| 순서 | 화면 뒤에서 일어나는 일 | 발표자가 설명할 말 |
|---|---|---|
| 1 | PDF → pdfplumber가 낱말과 위치를 읽음. 줄은 글자 아랫선으로 묶고, 쪽 가운데 빈틈으로 2단 구간을 찾아 왼쪽 단 → 오른쪽 단 순서로 읽음. 본문보다 작은 글자 줄은 표시해 둠 | "글자 위치만 읽고, 순서는 빈틈으로 정해요. AI·OCR은 안 써요." |
| 2 | **정규식 절 나누기**: `1 Introduction`·`3.2 Pre-training`·`II. RELATED WORK`·`A BSTRACT` 같은 제목 줄(번호가 1, 2, 3… 차례일 때만), `Abstract—` 같은 줄 초록, `References`에서 멈춤 | "절 제목은 정규식이 찾고, 번호 차례로 표 숫자 줄을 걸러요." |
| 3 | **정규식 거르기**: 이메일·소속(`… is with University`)·교신저자·저작권·학회 문단, 작은 글자(각주·캡션), 숫자뿐인 조각(표·수식). 끊긴 문단 잇기, 하이픈 단어 보존(`fine-tuned`) | "논문 앞머리와 각주는 정규식으로 빼요. 개인정보는 화면에 안 올려요." |
| 4 | 초록·본문·결론 쪽 묶기(`Conclusion`·`Discussion`·`Limitations`는 결론) | "읽을 쪽을 고르면 그 절이 분석돼요." |
| 5 | 최소 방어선 → 인용·수식을 가린 뒤 문장 분리 → 약어(regex 후보 + 첫 글자 맞추기) → 3줄 뼈대(신호 문구 → 위치 대체) → 표시 7종 → 흐름도·단어표 | "문장마다 무엇을 볼지는 전부 정규식이 정해요." |
| 6 | **정규식 표·그림**: `Table 3:`·`Figure 2:` 캡션 줄 → 캡션 옆 가로선 묶음(표) / 캡션 위 그림 요소(그림)로 영역을 정해 이미지로 자름 → 본문의 `Table 3`·`Fig. 2`를 처음 언급한 문장 아래에 배치 | "표를 찾는 것도, 어디에 놓을지도 정규식이 정해요." |
| 7 | ("번역하기" 버튼) 약어·인용·참조를 `<x>`로 보호, 형광펜 `<m>`·밑줄 `<u>`·문장 `<s>` 태그를 붙여 Claude Haiku로 전송 → 태그를 정규식으로 찾아 한국어 쪽 위치 복원. 긴 절은 4,000자 묶음으로 나눠 동시에 | "번역은 AI가, 한국어 쪽 표시 위치 복원은 정규식이 해요." |
| 8 | 결과를 사용자 브라우저에 저장(글 해시 → 번역). 같은 글이면 다시 부르지 않음 | "같은 논문은 다시 번역하지 않아요. 서버에는 안 남아요." |

**AI는 문장을 옮기고 뜻을 한 줄 풀고, 정규식은 읽는 길을 보여 준다.** 번역을 꺼도 1~6단계는 그대로 동작한다.

## 04. 처음 읽는 학생에게는 정보량보다 읽는 순서가 중요하다

**UI 기준:** v03 디자인 인계 자료([design/paperpath-v03/](design/paperpath-v03/README_FIRST.md))를 따른다. 단, 첫 화면 상단만 2026-11-04에 개정했다(이의상 결정 "ai번역 강조로 가고 생성 이미지 파일을 써"): 2단 히어로(왼쪽 소개 문구·AI-Powered Translation 배지, 오른쪽 이의상 님이 만든 배경 이미지 `static/hero.jpg`), 색 Deep Navy #152C49 · Academic Blue #3979B5 · Soft Blue #EAF3FC · White.

- 원문을 지우거나 바꾸지 않는다
- 자료를 넣기 전에는 입력 칸과 사용 순서만 보이고, 넣으면 입력 칸을 닫고 결과만 보인다("다시 넣기")
- 3줄 뼈대 → 원문·번역 → 이해를 돕는 자료 순서로 읽기를 안내한다. 빈 카드를 보여 주지 않는다
- 근거를 텍스트로 보여 준다("신호 문구로 찾음" / "추정" / "정의를 찾지 못함" / "번역기가 옮긴 위치"). 색만으로 전달하지 않는다
- 표·그림은 따로 모으지 않고 처음 언급한 문장 아래에 둔다(모아보기는 전체 목록으로만)
- AI 결과(번역·뜻 풀이)에는 "참고용"을 붙이고, 외부 전송을 화면에 안내한다
- 휴대폰 폭에서는 세로로 배치하고, 마우스 미리보기는 끈다

## 06. 정규식이 결과의 핵심 원인이 되는 곳

상태는 모두 구현·테스트 완료다(11/05). 전체 패턴과 설명은 `src/patterns.py`에 있다.

| 범주 | 패턴 요약 | 실측·예 | 일부러 놓치는 경우 |
|---|---|---|---|
| 최소 방어선 | 줄바꿈→공백, 연속 공백, 쪽번호 줄 `^\s*\d{1,4}\s*$`, 반복 머리말(같은 짧은 줄 3회 이상) | — | — |
| 하이픈 복원 | `DEHYPHEN` + 빈도표 판단: 붙인 말이 사전에 없고 뒤 조각이 단어면 하이픈 유지 | `fine-tuned`, `task-specific`, `state-of-the-art` 유지, `knowl-edge` → `knowledge` | `unsuper-vised`처럼 드물게 남음 |
| 문장 분리 | 인용·수식·URL 선마스킹 + `(?<=[.!?])\s+(?=[A-Z(\["'])` + 예외 약어 목록 | `i.e.`, `et al.`, `Eq. 4` 정상 | 예외 목록에 없는 약어 |
| 약어 | 괄호 안 후보 regex → 앞 단어 첫 글자 맞추기(대문자, 실패하면 전체 글자 재시도). 대문자 비율 0.4 미만 제외 | `GRU`, `RAG`, `BERT`, `CoT` | `XGBoost`, `BiLSTM`, `k-NN` → "정의를 찾지 못함" |

| 3줄 뼈대 | 신호 문구 4범주 → 위치 대체(공개 문장 제외, 미래·윤리 문장은 한계 카드) | 셋 다 채움 20% → 74% | 위치 관습을 따르지 않는 글 |
| 핵심 내용 밑줄 | 신호 문구가 가리키는 구간(12단어 이내, 끝 기능어 정리) | 평균 길이 18.8단어 → 12단어 상한 | — |
| 용어 설명·수치 | `refers to`·`, which is`·`such as`·`(i.e., …)`·동격 / `8.4%`·`accuracy of 74%` | 표시된 단어 14.3% → 18.0% | — |
| 반복 용어 | 3번 이상, 기능어·일반어 제외, 두 단어 용어 우선 | 초록당 3.4개, 25.5% | — |
| **PDF 절 제목** | `SEC_NUM_HEAD`(번호 차례 확인), `SEC_NAMED_HEAD`, `SEC_INLINE_ABSTRACT`, `SMALL_CAPS_HEAD`, `SEC_END` | 7편 모두 초록·참고문헌 경계 | 번호 없는 절이 이름 목록에 없을 때 |
| **PDF 앞머리·각주** | `EMAIL`, `PDF_FRONT_MATTER`(소속·교신저자·Index Terms·저작권·학회·Equal contribution), `PDF_NOISE_PARA`(각주·캡션) + 작은 글자 문단 | ViT 결론 26,571자 → 1,216자(참고문헌 분리) | 절 제목을 하나도 못 찾는 PDF |
| **표·그림** | `TABLE_CAPTION`, `FIGURE_CAPTION_NUM` / `TABLE_MENTION`, `FIGURE_MENTION` | 표 52/57, 그림 42/43 영역 | 캡션 없는 표, 캡션이 그림 위에 있는 형식 |

## 07. 번역은 AI(Claude Haiku), 보호와 위치는 정규식 — 번역은 켜고 끄는 층

**번역 엔진: Claude Haiku 5.5(`claude-haiku-5-5`, 2026-11-04 이의상 "Haiku로 하자").** `ANTHROPIC_API_KEY`가 없으면 DeepL API Free를 쓴다. 두 엔진 모두 같은 태그 방식이다. 번역을 꺼도 모든 regex 기능이 동작한다.

| 항목 | 내용 |
|---|---|
| 요금 | 입력 100만 토큰당 $0.10, 출력 $0.50[R12]. 논문 한 편 전체 약 $0.02 내외(요금표 추정). 이의상 님 계정 선불 충전($5), 자동 충전은 끄도록 안내 |
| 호출 | "번역하기"를 누를 때만. Claude로 번역하면 같은 김에 단어 뜻 풀이 1회 |
| 긴 절 | 태그를 뺀 글자 수 기준 4,000자 묶음으로 나눠 **동시에** 전송(순서 유지) |
| 짝 맞추기 | 문단 + `<s>` 태그 1회 → 어긋나면 번호 붙인 문장을 JSON 형식으로 1회 → 빠진 문장만 한 문장씩 동시에. (11/04 공개 사이트에서 한 문장씩 차례로 보내 55초 걸린 문제를 고침) |
| 오류 | 키·권한·한도·연결·거절·중간 끊김을 한국어 안내로. regex 기능은 계속 동작 |
| 사용 제한 (`src/usage.py`) | Claude: 한 번 4,000자 · 화면 60회 · 하루 300,000자 / DeepL: 3,000자 · 10회 · 30,000자 |
| 전송 안내 | 번역 칸과 입력 칸에 "Claude(Anthropic) API로 전송" 안내. 개인정보를 넣지 말라고 안내 |
| 키 | 로컬 `.env`, 공개 사이트는 Streamlit Secrets. 코드·커밋에 넣지 않음 |

**마스킹 실측 결과(30편):** 켬 201/203, 끔 173/203. 끔 쪽 차이 30개 중 27개는 표기 변환이었다. 수치를 가리면 틀린 숫자가 1건 나와서 수치는 보호에서 뺐다. 그래서 마스킹은 "번역 훼손 방지"보다 **영어 표시를 한국어 쪽 같은 자리에 옮기는 기준점** 역할로 설명한다.

**AI 뜻 풀이:** 단어(정규식·빈도표가 고른 전문용어와 반복 용어)와 그 단어가 처음 나온 문장을 Claude에 보내 JSON 형식으로 "이 논문에서의 뜻"을 한 줄씩 받는다. 보낸 단어만 반영하고 40개·80자로 제한한다. 단어표와 반복 용어 밑줄 툴팁(영어·한국어 쪽 모두)에 쓴다.

**말투 혼재**(습니다/한다)는 Claude 지시("-다"체)로 줄였고, 남는 경우는 한계로 공개한다.

**예상 질문과 답 (초안):**
- "결국 AI 번역기 아닌가요?" → 번역을 끄고 시연한다. 절 나누기·3줄 뼈대·표시·표/그림 배치·단어표 선정은 모두 정규식이고, AI는 번역과 한 줄 뜻만 쓴다. 첫 화면의 AI 번역 강조는 사용자에게 가장 와닿는 기능이라 앞에 둔 것이다
- "정규식으로 PDF를 어떻게 나눠요?" → 위치 읽기는 pdfplumber, 순서는 쪽 가운데 빈틈, 절 제목은 번호 차례를 확인하는 정규식
- "틀린 경우는요?" → 검증 탭의 실측표와 "추정"·"정의를 찾지 못함" 표시를 보여 준다
- "저작권은요?" → 서버에 저장하지 않고, 사용자 브라우저에만 둔다. 시험 PDF는 커밋하지 않았다

**마지막에 전달할 한 문장:** "번역기를 꺼도 동작합니다. 정규식이 논문을 나누고, 먼저 읽을 세 문장을 고르고, 표를 필요한 자리에 놓고, 어려운 단어를 골라 줍니다. AI는 그 옆에서 번역만 돕습니다."

## 13. AI 도구를 쓰는 방식

| 쓰는 곳 | 도구 | 사람이 확인하는 것 |
|---|---|---|
| 기획·문서 초안, 코드 작성 보조 | Claude Code (Anthropic) | 모든 결정과 컨펌은 이의상. 실제로 실행한 테스트·실측 결과만 기록 |
| 번역 (선택 층) | Claude Haiku 5.5 (기본), DeepL API Free (키가 없을 때) | 품질은 보증하지 않음. 태그 복원·짝 맞춤을 테스트와 실측으로 확인 |
| 단어 뜻 풀이 (선택) | Claude Haiku 5.5 | 단어 선정은 정규식·빈도표. 보낸 단어만 반영, "참고용" 표시 |

**정규식 규칙의 판단 근거는 사람이 설명할 수 있어야 한다.** AI가 만든 패턴도 테스트와 검수를 통과해야 채택한다.
