## 01. 먼저 합의할 한 장

**제품의 중심은 "대신 읽어 주기"가 아니라 "읽는 길 보여 주기"이고, 그 엔진은 정규식이다.** 기능 수보다 **6개 기능이 시연 중 터지지 않는 것**을 우선한다.

| 이번에 확정하는 방향 | 실제로 보여줄 경험 |
|---|---|
| 대상: **영어 논문을 처음 읽는 학부생** | 로그인, 요금, 설치 없이 첫 화면에서 바로 결과가 나온다 |
| 주 입력: **arXiv ID** (+ 텍스트 붙여 넣기) | ID를 넣으면 공식 API로 깨끗한 초록을 불러온다. 붙여 넣은 텍스트에도 최소 방어선(줄바꿈·공백·하이픈·쪽번호·반복 머리말 정리)을 적용한다 |
| **원문 3줄 뼈대** | 문제·방법·결과 원문 문장 3개가 뜬다. 카드마다 잡힌 신호 문구가 굵게 보이고, 한국어 이유 한 줄이 붙는다(예: "`results show` → 결과를 알리는 표현"). 신호 문구로 못 찾으면 "도입 문장 (배경·문제 추정)", "마무리 문장 (결과 추정)"으로 단정하지 않고 표시한다. 코드·데이터 공개 문장은 고르지 않고, 미래 연구·윤리 문장은 한계 카드로 보낸다 |
| 약어 → 풀네임 | `RLHF`에 마우스를 올리면 풀네임이 보인다. 찾지 못하면 "정의를 찾지 못함"으로 정직하게 표시한다 |
| 추측·가능성 표현 | `may (not necessarily) reflect`, `suggests`, `likely`를 한 등급으로 칠한다. `may be applied` 같은 가능·허용 뜻은 제외 목록으로 뺀다 |
| 영한 나란히 보기 (**켜고 끄기**) + **마스킹 비교 버튼** | "번역하기" 버튼을 누르면 마스킹 켬 번역 1회로 문장이 1:1로 짝지어진다. "마스킹 끔과 비교" 버튼을 누를 때만 두 번째 번역을 한다. 결과는 캐시하고, 오류가 나도 regex 기능은 계속 동작한다 |
| 근거 규칙 + **읽기 전용 단계 보기** | 하이라이트마다 근거 규칙이 보인다. 미리 준비한 규칙을 켜고 끄며 결과가 바뀌는 모습을 보여 준다(자유 입력 없음) |

**핵심 시연:** arXiv ID를 넣는다 → 원문 3줄 뼈대가 뜬다 → 약어와 추측 표현의 툴팁에서 근거 규칙을 확인한다 → "추측 제외 규칙"을 끄면 `may be applied`가 잘못 칠해지는 모습을 보여 준다 → 번역을 켜고, 마스킹을 껐을 때와 비교한다.

**현재 확보 상태 (2026-11-03 로컬 실행 기준):**
- arXiv cs.CL 초록 300건(CC0, 저자 필드 제외)
- 마스킹 왕복: 2,010문장 불일치 0
- DeepL 실제 번역: 보호 토큰 13/13 보존
- 약어 통과: `GRU`·`YOLO`·`LoRA`·`RAG`·`BERT` / 실패: `BiLSTM`·`XGBoost`·`k-NN`·`CoT`. 전체 글자 재시도를 넣으면 `CoT`도 통과(2026-11-04 실측)
- DeepL 지연(2026-11-04): 3문장 1회 호출 약 1.24초. 입력 3문장에 결과 3개로 개수 일치
- **마스킹 끔 결과**: 같은 3문장에서 `BERT`·`3.1%`·`[4]`가 그대로 보존됨. 차이는 `Table 1`→`표 1`과 `[4]` 앞 띄어쓰기뿐. 마스킹의 효과가 작을 수 있어 30편 실측으로 확인한다
- 뼈대 문장 신호 문구 검출률(샘플 300건)

| 범주 | 검출률 |
|---|---|
| 방법 | 72% |
| 결과 | 61% |
| 문제 | 29% |
| 문제·방법·결과 셋 다 | **16%** |
| 셋 다 없음 | **15%** |

뼈대 검출률이 낮기 때문에 대체 규칙이 필요하다. 다만 마지막 문장이 코드·데이터 공개나 URL인 초록이 6%(19/300)라서, 대체할 때 이런 문장은 건너뛴다.
- 추측 표현: `may/might/could`는 300건에 48회 나왔다(초록 1편당 약 0.16회). 조동사 뒤 동사는 30종 넘게 흩어져 있다
- 이 때문에 닫힌 동사 목록 방식은 쓰지 않는다
- 샘플은 대표성이 없다

**한 줄 차별화:** **AI가 대신 읽어 주는 대신, 정규식이 읽는 길을 보여 주는 논문 도우미.** 번역기 래퍼가 아니라, 번역을 꺼도 동작하는 regex 독해 엔진이다.

## 02. 해결할 문제와 기존 논문 AI의 가치

학생이 영어 논문을 어려워하는 이유는 다섯 가지가 겹친다.
- 약어·전문어
- 요점 찾기
- 주장 강도 판단
- 긴 문장 구조
- 배경지식과 참조 왕복

과학 논문의 약어 비율 증가[R01]와 가독성 하락[R02]도 보고되었다. **이번 범위는 앞의 세 가지(약어, 요점, 주장 강도)에 집중한다.** 긴 문장 구조는 P1이고, 배경지식은 범위 밖이다.

| 기존 자산·관찰 | 우리가 바꿀 전달 방식 |
|---|---|
| Semantic Reader: Goal/Method/Result 하이라이트, 용어 정의 툴팁[R03][R04][R05] | 같은 방향의 표시를 **regex 규칙**으로 하고 근거 규칙을 보여 준다 |
| SciSpace·Explainpaper: LLM이 쉬운 말로 설명[R06] | 설명을 생성하지 않고 원문과 (선택) 번역을 나란히 둔다 |
| 범용 챗봇 "3줄 요약" | 원문에서 고른 **3줄 뼈대**. 지어낸 문장이 없고 근거 등급이 보인다 |
| scite: 바깥 인용의 지지·반박 | **논문 안의** 추측·확신 표현을 문맥 창 규칙으로 칠한다 |

**검증할 변화:**
- 규칙 출력의 정밀도(약어·추측·뼈대)
- 3줄 뼈대 채움률(대체 규칙 전후)
- 마스킹이 번역 훼손을 얼마나 줄이는가. 작을 가능성이 있으며 결과대로 보고한다

## 03. 입력하면 화면 뒤에서 무엇이 움직일까

| 순서 | 화면 뒤에서 일어나는 일 | 발표자가 설명할 말 |
|---|---|---|
| 1 | arXiv ID → 공식 API로 초록 불러오기 (또는 붙여 넣은 텍스트) | "공식 API라서 텍스트가 깨끗해요." |
| 2 | 최소 방어선: 줄바꿈→공백, 연속 공백 제거, 하이픈 개행 복원, 숫자만 있는 줄(쪽번호)·반복되는 짧은 줄(머리말) 제거 | "복사할 때 따라온 잔재를 정규식 다섯 줄로 걸러요." |
| 3 | 인용·수식을 먼저 마스킹한 뒤 문장 분리 | "`et al.`이나 `Eq. 4`의 마침표에서 끊기지 않게 해요." |
| 4 | 약어: regex로 괄호 안 후보 찾기 → Python 함수로 첫 글자 맞추기(대문자 → 안 되면 전체 글자로 재시도) | "후보는 정규식이 찾고, 맞추기는 짧은 함수가 해요." |
| 5 | 뼈대 판정 → 3줄 선택. 신호 문구가 없으면 도입·마무리 문장으로 대체(코드·URL 문장 제외, 미래 연구·윤리 문장은 한계 카드로). 카드에 신호 문구 강조 + 한국어 이유 | "신호 문구로 찾고, 왜 골랐는지 한 줄로 알려 줘요. 없으면 '도입 문장', '마무리 문장'이라고 솔직하게 표시해요." |
| 6 | 추측·가능성 표현 판정(부사·부정어 2개까지 허용, 가능·허용 뜻은 제외) | "`may not necessarily`처럼 단어가 끼어도 잡고, `may be applied`는 빼요." |
| 7 | ("번역하기" 버튼) 보호 마스킹 → DeepL 1회 → 개수 확인(다르면 문단 단위) → 복원 → 조사 띄어쓰기 정리. "비교" 버튼을 누르면 마스킹 끔 번역을 추가로 호출 | "포장한 토큰은 번역기가 건드리지 못해요. 비교는 버튼을 눌렀을 때만 해요." |

**번역기는 문장을 옮기고, 정규식은 읽는 길을 보여 준다.** 번역을 꺼도 1~6단계는 그대로 동작한다.

## 04. 처음 읽는 학생에게는 정보량보다 읽는 순서가 중요하다

**구체적인 화면 배치, 색, 디자인은 이의상 님의 지시를 받아 정한다.** 어떤 디자인이든 아래 기능 원칙은 지킨다.

- 원문을 지우거나 바꾸지 않는다
- 첫 화면에서 **입력 → regex 표시 → 결과**가 바로 보인다(과제 조건)
- 3줄 뼈대 → 세부 표시 순서로 읽기를 안내한다. 빈 카드를 보여 주지 않는다
- 근거를 텍스트로 보여 준다("신호 문구로 찾음" / "도입 문장·마무리 문장 (추정)" / "정의를 찾지 못함"). 색만으로 전달하지 않는다
- 외부 번역 서비스로 전송된다는 사실을 화면에 안내한다

## 06. 정규식이 결과의 핵심 원인이 되는 곳 (P0)

"확인"은 2026-11-03 프로토타입에서 실행한 결과이고, "신규"는 설계 단계다.

| 범주 | 패턴 요약 | 상태·예 | 일부러 놓치는 경우 |
|---|---|---|---|
| 최소 방어선 | 줄바꿈→공백 `(?<!\n)[ \t]*\n[ \t]*(?!\n)`, 연속 공백 `[ \t]{2,}`, 쪽번호 줄 `^\s*\d{1,4}\s*$`, 반복 머리말(같은 짧은 줄 3회 이상) | 앞의 둘은 확인, 뒤의 둘은 신규 | 캡션·각주·2단 꼬임(P1 또는 범위 밖) |
| 하이픈 복원 | `(?<=[a-z])-[ \t]*\n[ \t]*(?=[a-z])` → 제거 | 확인 | 원래 하이픈이 있던 단어 |
| 문장 분리 | 인용·수식 선마스킹 + `(?<=[.!?])\s+(?=[A-Z(\["'])` + 예외 약어 목록 | 확인: `i.e.`, `vs.`, `ca.`, `Eq. 4`, `Ref. 12`, `et al.` 정상 | 예외 목록에 없고 대문자가 뒤따르는 약어 |
| 약어 | **regex**: 괄호 안 후보 `\(\s*(?P<abbr>(?=(?:[^A-Z)]*[A-Z]){2})[A-Za-z][A-Za-z0-9-]{1,11})\s*\)` → **Python 함수**: 앞 단어 첫 글자 맞춤(하이픈 조각 포함). 약어의 대문자로 실패하면 전체 글자로 한 번 재시도 | 확인: `GRU`, `YOLO`, `LoRA`, `RAG`, `BERT`, 재시도로 `CoT`(9사례 중 6) | `XGBoost`, `BiLSTM`, `k-NN`은 "정의를 찾지 못함"으로 표시. 동적 regex 생성은 4차 개정에서 삭제. Schwartz & Hearst[R11]는 비교 대상으로만 언급 |
| 추측·가능성 (단일 등급) | 표시: `\b(?:may\|might\|could)\b` 또는 인식 표현 `\b(?:suggests?\|indicates?\|likely\|possibly\|perhaps\|appears?\s+to\|seems?\s+to)\b` / 제외: `\b(?:may\|can\|could\|might)\s+(?:(?:also\|not\|\w+ly)\s+){0,2}be\s+(?:(?:\w+ly)\s+)?(?:applied\|used\|extended\|adapted\|employed\|deployed\|integrated\|combined)\b` | 단어 목록형 확인, 제외 확장은 신규. 테스트: `may not necessarily reflect` 표시, `could also be easily extended` 제외 | 문장을 넘는 문맥. 3등급 분류는 폐지(실측 92%가 "확인 필요"로 쏠림) |
| 확신 | `demonstrat(?:e\|es\|ed\|ing)\|significantly\|state[- ]of[- ]the[- ]art…` | 확인 | 통계적 유의성과 강조의 구분 |
| 뼈대 문장 | 신호 문구 4범주(문제·방법·결과·한계) | 확인. 검출률은 §01 표 | 신호 문구 없는 문장 |
| **뼈대 위치 대체** | 신호 문구가 없을 때의 대체 규칙(표 아래). 공개 문장: `https?://\|github\|\b(?:code\|data(?:set)?s?\|models?)\b[^.]{0,40}\b(?:is\|are\|will be)\s+(?:publicly\s+\|made\s+\|freely\s+)?(?:available\|released)\|\bwe (?:release\|make)\b` / 미래·윤리 문장: `\b(?:future (?:work\|research\|directions?)\|we leave\|broader impacts?\|ethic(?:s\|al\|ally)\|limitations?\|open (?:question\|problem)s?)\b` | 신규. 샘플 마지막 문장 중 공개 19건(6%), 미래·한계·윤리 10건(3%) 검출 확인. 채움률·오탐 재측정 예정 | 위치 관습을 따르지 않는 초록. 라벨이 "추정"이라 단정하지 않음 |
| 참조·인용 | `\[\d+(?:\s*[,–-]\s*\d+)*\]`, `\(… et al\.,? \d{4}\)`, `Fig\.?\s*\d+` | 확인 | 각주형 인용 |
| 번역 보호 | 약어·참조·수치 → `<x>` | 확인: 13/13 | URL 안 특수문자 일부 |
| 번역 후처리 | 조사 앞 공백 제거(닫힌 조사 목록), "제Section" 제거 | "제" 제거 확인, 조사 신규 | 조사 선택(받침) 오류 |

뼈대 위치 대체 규칙:
- "도입 문장 (배경·문제 추정)" = 첫 문장
- "마무리 문장 (결과 추정)" = 공개 문장과 미래·윤리 문장을 뺀 뒤쪽 문장 가운데, 수치나 결과 동사가 있는 문장을 우선
- 미래·윤리 문장은 버리지 않고 "한계" 카드 후보로 보낸다
- 방법 = "we/our"가 들어간 첫 문장
- 각 카드에는 잡힌 신호 문구를 굵게 표시하고, 규칙별 한국어 이유 한 줄을 붙인다. 이유 문구는 `patterns.py`의 규칙 설명에서 가져온다

## 07. 번역은 DeepL, 보호는 정규식 — 번역은 켜고 끄는 층

**번역 엔진은 DeepL API Free로 결정했다(2026-11-03, 이의상 선택). 번역을 꺼도 모든 regex 기능이 동작해야 한다.**

| 확인한 사항 | 근거 |
|---|---|
| 무료 등급 월 500,000자 | 공식 문서[R09] |
| Free 엔드포인트 `api-free.deepl.com`, Free 키는 끝이 `:fx`, `DeepL-Auth-Key` 헤더 | 공식 문서[R08] |
| `tag_handling=xml` + `ignore_tags=x`이면 `<x>` 안의 텍스트를 번역하지 않음 | 공식 문서[R10] |
| 무료 등급에서 보낸 텍스트의 보관·활용 여부 | **미확인**. 화면에 전송 안내를 한다 |

**호출 방식 (지연 실행):**
- Streamlit은 입력이 바뀔 때마다 화면을 다시 계산한다. 그래서 번역은 **"번역하기" 버튼을 눌렀을 때만** 마스킹 켬으로 1회 호출한다
- **"마스킹 끔과 비교"** 버튼을 누를 때만 두 번째 호출을 한다
- 모든 결과는 문장 단위로 캐시한다
- 실측 지연은 3문장 1회 약 1.24초다(2026-11-04). 입력이 길면 늘어난다
- **오류 처리:** 429(요청 과다)·456(한도 초과)·네트워크 오류가 나면 앱을 멈추지 않는다. "번역을 잠시 쓸 수 없음"이라고 안내하고, 캐시가 있으면 캐시를 보여 준다. regex 기능은 계속 동작한다
- **개수 안전장치:** 문장마다 따로 보내고 DeepL의 재분리를 꺼서(`split_sentences=0`) 구조상 개수가 항상 같다(실측 3/3). 그래도 `len(en) != len(ko)`이면 문단 단위로 보여 준다

**마스킹 on/off는 두 가지로 나눈다:**
- **서비스 기능(P0-5):** 위의 "비교" 버튼. 사용자 텍스트에 대해서만 실행한다
- **검증 결과(§11):** 초록 30편으로 훼손 비율을 미리 실측해 "검증" 탭과 README에 싣는다. 약 4만 자로 월 한도의 약 8%다. 시연 중에 실행하지 않는다

**⚠️ 마스킹 효과가 작을 수 있다 (2026-11-04 발견):**
- 3문장을 마스킹 끔으로 번역해도 `BERT`·`3.1%`·`[4]`가 보존됐다
- 그래서 30편 실측을 **2주차로 앞당겨** 먼저 확인한다
- 훼손률이 낮으면 그대로 공개한다. 비교 버튼은 시연의 중심에서 빼고, 마스킹의 역할을 다시 설명한다
  - 보호된 약어·인용 위치를 기준점으로 영어 쪽 하이라이트를 한국어 쪽에 정확히 옮기는 역할
  - 용어 일관성(`Table`→`표` 같은 변형 방지)
- 결과를 보기 전에 "마스킹이 번역 훼손을 크게 줄인다"고 주장하지 않는다

**말투 혼재**(습니다/한다)는 남은 문제다. 시간이 허락하면 어미 대응표로 통일하고(P1), 아니면 한계로 공개한다.

**운영 원칙:**
- 키는 `.env`에만 둔다
- 시연 예시는 캐시한다
- 무료 한도를 넘는 호출이나 유료 전환은 승인 없이 하지 않는다

## 11. 정확도는 설계가 아니라 결과로 입증한다

아래 숫자는 **사전 목표**이며 현재 실적이 아니다.

| 평가 | 계획과 완료 기준 |
|---|---|
| 규칙 정밀도 (검수형) | 초록 20편에서 규칙 출력을 "맞음/틀림"으로 검수한다(예상 3~4시간). 목표: 약어 0.9 이상, 추측·가능성 0.8 이상. 뼈대는 근거별(신호 문구/도입·마무리 추정) 정밀도를 보고하고, 대체 문장 중 코드·URL 문장이 섞인 수를 따로 집계 |
| 규칙 재현율 (소표본) | 10편에서 약어·추측을 직접 표시해 놓친 비율을 보고 |
| 3줄 뼈대 채움률 | 샘플 전체에서 대체 규칙 전후 비교. 현재 신호 문구만으로 셋 다 채움 16% |
| 마스킹 기여 (검증 탭) | 2주차에 30편 on/off 번역을 미리 실측. 보호 토큰 훼손률 비교, on에서 보존율 100% 목표. 서비스 기능이 아니라 평가 결과로 표시. 소량 사전 측정에서는 끔 상태에서도 대부분 보존되었으므로, 차이가 작게 나와도 그대로 보고 |

검수는 규칙을 만든 시점과 다른 시점에 하고, 목표에 못 미치면 못 미친 대로 보고한다.

## 13. AI 도구를 쓰는 방식

| 쓰는 곳 | 도구 | 사람이 확인하는 것 |
|---|---|---|
| 기획·문서 초안, 코드 작성 보조 | Claude Code (Anthropic) | 모든 결정과 컨펌은 이의상. 실제로 실행한 테스트 결과만 보고 |
| 번역 (선택 층) | DeepL API Free | 번역 품질은 보증하지 않고, 보호 토큰 보존을 테스트로 확인 |
| 학술 어휘 뜻 초안 (P1) | AI 초안 | 사람이 검수하고 출처를 명시 |

**정규식 규칙의 판단 근거는 사람이 설명할 수 있어야 한다.** AI가 만든 패턴도 테스트와 검수를 통과해야 채택한다.
