## 01. 먼저 합의할 한 장

**제품의 중심은 "대신 읽어 주기"가 아니라 "읽는 길 보여 주기"이고, 그 엔진은 정규식이다.** 원문은 그대로 두고, 정규식이 끊어 읽을 곳·먼저 읽을 문장·조심할 표현을 표시한다. 번역은 꺼도 제품이 성립하는 보조 층이다.

| 이번에 확정하는 방향 | 실제로 보여줄 경험 |
|---|---|
| 대상: **영어 논문을 처음 읽는 학부생** | 과제 논문을 넣으면 첫 화면에서 바로 결과가 나온다. 로그인, 요금, 설치가 없다 |
| **원문 3줄 뼈대** | 맨 위에 문제·방법·결과 **원문 문장 3개**와 그 번역이 나온다. 생성 요약이 아니라서 지어낸 내용이 없다 |
| **끊어 읽기 + 구문 신호** | 40단어 문장이 `, which` / `that` / `although` 경계에서 들여쓰기로 끊긴다. "가주어 It … that", "관계절", "수동태" 꼬리표가 붙는다 |
| 약어 → 풀네임 (확신도 2단계) | `RLHF`에 마우스를 올리면 풀네임이 보인다. 규칙이 부분적으로만 맞으면 "후보"로 표시한다 |
| 추측·확신 (문맥 창) | `may indicate`는 추측, `may be applied`는 표시하지 않는다. 애매하면 연한 색 "확인 필요"로 표시한다 |
| **PDF 노이즈 탐지기** | 페이지 번호, 머리말, 캡션, 각주가 걸러진다. "제거된 줄 보기"로 무엇을 지웠는지 확인한다 |
| 영한 문장 나란히 보기 (**켜고 끄기**) | 켜면 영어와 한국어 문장이 1:1로 짝지어진다. 약어, 인용, 수치는 regex 마스킹으로 보존된다 |
| **마스킹 on/off 실험** | 마스킹을 끄면 `BERT`·`[3, 5]`가 망가지는 비율이 몇 %인지 실측 수치로 보여 준다 |
| **Regex 실험실** | 한 문장이 전처리 → 분리 → 마스킹 → 추출을 거치는 단계를 보여 준다. 평가자가 패턴을 고쳐 보면 결과가 바로 바뀐다 |
| 모든 표시에 근거 규칙 | 하이라이트마다 "규칙 HEDGE_EPISTEMIC"처럼 어떤 패턴이 잡았는지 보인다 |

**핵심 시연:** 과제 논문 한 단락을 붙여 넣는다 → 노이즈가 걸러지고 원문 3줄 뼈대가 뜬다 → 가장 긴 문장을 끊어 읽기로 펼친다 → 약어와 추측 표현의 툴팁에서 근거 규칙을 확인한다 → 번역을 켜고, 마스킹을 껐을 때와 비교한다 → Regex 실험실에서 패턴 하나를 고쳐 결과가 바뀌는 모습을 보여 준다.

**현재 확보 상태 (2026-11-03 로컬 실행 기준):**
- arXiv cs.CL 초록 300건(CC0, 저자 필드 제외)
- 이 샘플에서 초록 1편당 약어 정의 수: 2012년 0.22 → 2025년 1.04
- 마스킹 왕복: 2,010문장 불일치 0
- DeepL 실제 번역: 보호 토큰 13/13 보존
- 경계 사례 점검 결과

| 구분 | 결과 |
|---|---|
| 약어 통과 | `GRU`, `YOLO`, `LoRA`, `RAG`, `BERT` |
| 약어 실패 | `BiLSTM`, `XGBoost`, `k-NN`, `CoT` |
| 문장 분리 | `i.e.`, `vs.`, `ca.`, `Eq. 4`, `Ref. 12`, `et al.` 8문장 모두 정상 |

샘플은 대표성이 없으며, 평가용 검수와 pytest는 아직 없다.

**한 줄 차별화:** **AI가 대신 읽어 주는 대신, 정규식이 읽는 길을 보여 주는 논문 도우미.** 번역기 래퍼가 아니라, 번역을 꺼도 동작하는 regex 독해 엔진이다.

## 02. 해결할 문제와 기존 논문 AI의 가치

학생이 영어 논문을 어려워하는 이유는 다섯 가지가 겹친다.
- 약어·전문어
- 요점 찾기
- 주장 강도 판단
- 긴 문장 구조
- 배경지식과 참조 왕복

연구로도 과학 논문의 약어 비율 증가[R01]와 가독성 하락[R02]이 보고되었다.

기존 논문 AI는 연구자·석박사 중심으로 발전했고, 판단 근거가 보이지 않는다. 그 이유는 시장 구조를 보고 우리가 추론한 것이다.
- 지불 주체가 기관이다
- 연구자는 사용 빈도가 높다
- 가끔 쓰는 사람은 범용 챗봇이 흡수한다
- 비전문가에게 틀린 요약을 줄 때의 책임 부담이 크다

| 기존 자산·관찰 | 우리가 바꿀 전달 방식 |
|---|---|
| Semantic Reader: Goal/Method/Result 하이라이트, 용어 정의 툴팁[R03][R04][R05] | 같은 방향의 표시를 **regex 규칙**으로 하고 근거 규칙을 보여 준다 |
| SciSpace·Explainpaper: LLM이 쉬운 말로 설명[R06] | 설명을 생성하지 않는다. 대신 **끊어 읽기와 구문 신호**로 문장 구조를 보여 준다 |
| 범용 챗봇 "3줄 요약" | 원문에서 고른 **3줄 뼈대**. 지어낸 문장이 없고 원문 위치로 이동할 수 있다 |
| scite: 바깥 인용의 지지·반박 | **논문 안의** 추측·확신 표현을 문맥 창 규칙으로 칠한다 |

**검증할 변화:**
- 규칙 출력의 정밀도(약어·추측·뼈대)
- 마스킹이 번역 훼손을 얼마나 줄이는가
- 소규모 학생 테스트에서 도구를 쓸 때 이해 문제 정답과 소요 시간이 어떻게 달라지는가(§11)

## 03. 붙여 넣으면 화면 뒤에서 무엇이 움직일까

아래는 **직접 작성한 예시문** 기준의 설명이다. 실제 논문이 아니다.

| 순서 | 화면 뒤에서 일어나는 일 | 발표자가 설명할 말 |
|---|---|---|
| 1 | **노이즈 탐지**: 페이지 번호·반복 머리말·캡션·각주·이메일 줄 제거, 2단 편집 섞임 의심 시 경고 | "PDF 복사 잔재를 정규식으로 찾아 지우고, 지운 줄은 다 보여 줘요." |
| 2 | 하이픈 개행 복원, 공백 정리 | "끊긴 단어를 이어 붙여요." |
| 3 | 인용·수식을 먼저 마스킹한 뒤 문장 분리. 예외 약어는 코퍼스에서 자동 수집 | "`et al.`이나 `Eq. 4`의 마침표에서 문장이 끊기지 않게 해요." |
| 4 | 약어 정의 탐색(첫 글자 → 글자 단위 → 중첩 약어 순서), 확신도 판정 | "`BiLSTM`은 Bi + 앞에서 정의된 LSTM으로 풀어요." |
| 5 | 뼈대 문장 판정 → 원문 3줄 선택 | "요약을 만드는 게 아니라 원문에서 골라요." |
| 6 | 긴 문장 끊어 읽기, 구문 신호 꼬리표 | "관계사와 접속사 앞에서 끊고, 가주어 구문을 표시해요." |
| 7 | 추측·확신 문맥 창 판정 | "`may` 뒤에 무엇이 오는지 보고 추측인지 가능성인지 나눠요." |
| 8 | (번역 켬) 보호 마스킹 → DeepL → 복원 → 조사 띄어쓰기·말투 정규화 | "포장한 토큰은 번역기가 건드리지 못하고, 군더더기는 정해진 규칙으로 정리해요." |

**번역기는 문장을 옮기고, 정규식은 읽는 길을 보여 준다.** 번역을 꺼도 1~7단계는 그대로 동작한다.

## 04. 처음 읽는 학생에게는 정보량보다 읽는 순서가 중요하다

**구체적인 화면 배치, 색, 디자인은 이의상 님의 지시를 받아 정한다.** 어떤 디자인이든 아래 기능 원칙은 지킨다.

- 원문을 지우거나 바꾸지 않는다. 노이즈 제거도 "제거된 줄 보기"로 되돌려 볼 수 있어야 한다
- 첫 화면에서 **입력 → regex 표시 → 결과**가 바로 보인다(과제 조건). 번역은 그다음 층이다
- 3줄 뼈대 → 끊어 읽기 → 세부 표시 순서로 읽기를 안내한다
- 영어 문장과 한국어 문장은 같은 순서·같은 단위로 짝지어 보인다
- 색만으로 의미를 전달하지 않는다. "추측", "관계절" 같은 텍스트 꼬리표를 함께 둔다
- 외부 번역 서비스로 전송된다는 사실을 화면에 안내한다("개인정보를 넣지 마세요")

## 06. 정규식이 결과의 핵심 원인이 되는 곳

과제의 핵심은 regex로 영어 텍스트를 처리하는 것이다. 아래 표시는 **regex를 빼면 아무것도 남지 않는다.** "확인"은 2026-11-03 프로토타입에서 실행한 결과이고, "신규"는 설계 단계다.

| 범주 | 패턴 요약 | 상태·예 | 일부러 놓치는 경우 |
|---|---|---|---|
| 노이즈 탐지 | `^\s*\d{1,4}\s*$`(쪽번호), `^(?:Fig(?:ure)?\|Table)\s*\d+[.:]`(캡션), 3회 이상 반복되는 줄(머리말), 이메일·LaTeX 잔재 | 신규 | 2단 편집 섞임은 복원하지 않고 경고만 한다 |
| 하이픈 복원 | `(?<=[a-z])-[ \t]*\n[ \t]*(?=[a-z])` → 제거 | 확인: `termi-\nnology` → `terminology` | 원래 하이픈이 있던 단어 |
| 문장 분리 | 인용·수식 선마스킹 + `(?<=[.!?])\s+(?=[A-Z(\["'])` + 예외 약어(코퍼스에서 `\b[A-Za-z]{1,5}\.\s+[a-z]`로 수집) | 확인: `i.e.`, `vs.`, `ca.`, `Eq. 4`, `Ref. 12`, `et al.` 정상 | 예외 목록에 없고 대문자가 뒤따르는 약어(예: `U.S. Army`) |
| 약어 1단계 | 괄호 안 약어 + 단어 첫 글자 맞춤(하이픈 조각 포함) | 확인: `GRU`, `YOLO`, `LoRA`, `RAG`, `BERT` | — |
| 약어 2단계 | 글자 단위 순서 매칭(Schwartz & Hearst 계열[R11]) | 신규: `CoT`, `XGBoost` 대상 | 첫 글자가 단어 시작과 맞지 않는 경우는 "후보" |
| 약어 3단계 | 중첩 약어(`Bi` + 기정의 `LSTM`), 소문자 접두(`k-NN`) 전용 패턴 | 신규: `BiLSTM`, `k-NN` 대상 | — |
| 추측 (문맥 창) | 확정: `\b(?:may\|might\|could)\s+(?:\w+ly\s+)?(?:indicate\|suggest\|reflect\|explain\|be\s+due\s+to)\b` / 제외: `\b(?:may\|can\|could)\s+(?:also\s+)?be\s+(?:applied\|used\|extended\|adapted)\b` / 나머지는 "확인 필요" | 확인: `may indicate` O, `may be applied` X | 문장을 넘는 문맥 |
| 확신 | `demonstrat(?:e\|es\|ed\|ing)\|significantly\|state[- ]of[- ]the[- ]art…` | 확인 | 통계적 유의성과 강조의 구분 |
| 뼈대 문장 | 문제·방법·결과·한계 신호 문구 4범주 → 원문 3줄 선택 | 뼈대 확인, 3줄 선택은 신규 | 신호 문구 없는 문장은 "찾지 못함" |
| **끊어 읽기** | 경계: `,\s+(?=which\|where\|who\|whereas\|while\|although)`, `\s(?=that\s)`, `;\s`, 문장 중간 전치사구 앞(`\s(?=(?:by\|through\|via\|using)\s)`) | 신규 | 쉼표 없는 제한적 관계절 일부 |
| **구문 신호** | 가주어 `\bIt\s+is\s+(?:\w+\s+)?(?:\w+ed\|important\|necessary\|possible\|clear)\s+(?:that\|to)\b`, 수동태 `\b(?:is\|are\|was\|were\|be\|been)\s+(?:not\s+\|\w+ly\s+)?\w+(?:ed\|wn\|ven\|ten\|ght)\b`, 관계절 `,\s+which\b` | 수동태 확인, 나머지 신규 | 불규칙 과거분사 일부 |
| 참조·인용 | `\[\d+(?:\s*[,–-]\s*\d+)*\]`, `\(… et al\.,? \d{4}\)`, `Fig\.?\s*\d+` | 확인 | 각주형 인용 |
| 번역 보호 | 약어·참조·수치 → `<x>` | 확인: 13/13 | URL 안 특수문자 일부 |
| 번역 후처리 | 조사 앞 공백 `(?<=[A-Za-z0-9%)\]])\s+(?=(?:은\|는\|이\|가\|을\|를\|의\|에\|와\|과\|도\|로)\b)`, "제Section" 제거, 말투 대응표(`습니다`→`다` 등) | "제" 제거 확인, 나머지 신규 | 조사 선택(받침) 자체의 오류 |
| 학술 어휘 (P1) | 규칙 변화 생성(`-s/-es/-ies`, `-ed/-ied`, e 탈락 `-ing`, 자음 중복) + 불규칙 예외표 | 신규 | 커버리지 90% 미만이면 spaCy 표제어 추출을 보조로 쓴다 |

## 07. 번역은 DeepL, 보호는 정규식 — 그리고 번역은 켜고 끄는 층

**번역 엔진은 DeepL API Free로 결정했다(2026-11-03, 이의상 선택). 번역은 기본값 켜짐/꺼짐 여부를 UI 지시에 따라 정하되, 꺼도 모든 regex 기능이 동작해야 한다.**

| 확인한 사항 | 근거 |
|---|---|
| 무료 등급 월 500,000자 | 공식 문서[R09] |
| Free 엔드포인트 `api-free.deepl.com`, Free 키는 끝이 `:fx`, `DeepL-Auth-Key` 헤더 | 공식 문서[R08] |
| `tag_handling=xml` + `ignore_tags=x`이면 `<x>` 안의 텍스트를 번역하지 않음 | 공식 문서[R10] |
| 무료 등급에서 보낸 텍스트의 보관·활용 여부 | **미확인**. 확인 전까지 화면에 전송 안내를 한다 |

**마스킹 on/off 실험 (regex 기여의 정량화):**
- 초록 30편을 마스킹 켬과 끔으로 각각 번역한다
- 약어·인용·수치의 훼손 비율을 비교한다
- 예상 사용량은 약 4만 자로, 월 한도의 약 8%다
- 같은 번역 결과로 조사 띄어쓰기·말투 오류 건수도 센다

**문장별 번역의 성질:** 문장마다 따로 번역해서 짝짓기 때문에, 한 문장이 잘못 끊겨도 다른 짝은 밀리지 않는다(분리 오류 비전파). 이 성질은 테스트로 고정한다.

**운영 원칙:**
- 키는 `.env`에만 둔다(커밋 금지)
- 시연 예시는 캐시한다
- 무료 한도를 넘는 호출이나 유료 전환은 승인 없이 하지 않는다

## 10. 4주 안에 연결하는 순서

개발의 기준은 **번역을 꺼도 끊김 없는 3분 시연**이다. 규칙과 테스트를 먼저 고정한다.

| 시기 | 할 일 | 눈으로 확인할 결과 |
|---|---|---|
| 1주차 11/03–11/09 (Phase 2) | 계획서 확정, DeepL 키(완료), **UI 지시 반영 프로토타입 2차**: 3줄 뼈대, 끊어 읽기 초안, 번역 켜고 끄기 | 단락 하나로 3줄 뼈대 + 끊어 읽기 + (켜면) 영한 나란히 → **컨펌** |
| 2주차 11/10–11/16 (Phase 3) | `src/` 모듈화, `patterns.py` 이전, pytest(경계 사례: 축약형·하이픈·대소문자·둥근 따옴표·약어 실패 4종·분리 예외 100문장), 노이즈 탐지기, 약어 2·3단계 | `py -I -m pytest` 통과, BiLSTM·XGBoost·k-NN·CoT 처리 |

| 4주차 11/24–11/30 (Phase 4) | UI 완성, **소규모 유용성 테스트(5~8명)**, (승인 시) 배포, README·3분 시나리오·예상 질문, 리허설 2회 | 처음부터 끝까지 시연 성공, 오프라인 캐시 시연 가능 |

**마감 게이트:** 정확한 제출일이 확인되면 다시 계산한다. 늦어지면 P1 → Regex 실험실의 패턴 수정 기능 → 유용성 테스트 규모 순으로 줄인다. 끊어 읽기·3줄 뼈대·마스킹 실험은 마지막까지 유지한다.

**범위 기준:** 배포는 외부 공개 행위라서 **이의상 님의 승인 후**에만 한다. 사용자 테스트는 참여자의 동의를 받고 익명으로 한다.

## 11. 정확도는 설계가 아니라 결과로 입증한다

아래 숫자는 **사전 목표**이며 현재 실적이 아니다.

| 평가 | 계획과 완료 기준 |
|---|---|
| 규칙 정밀도 (검수형) | 초록 20편에서 규칙 출력을 "맞음/틀림"으로 검수하는 작은 화면을 쓴다(예상 3~4시간). 목표: 약어 정밀도 0.9 이상, 추측 정밀도 0.8 이상. 뼈대는 범주별 정밀도만 보고 |
| 규칙 재현율 (소표본) | 10편에서 약어·추측을 직접 표시해 놓친 비율을 보고 |
| 마스킹 기여 | 30편 on/off 번역. 보호 토큰 훼손률을 비교하고, on에서 보존율 100% 목표 |
| 문장 분리 | 예외 약어가 들어간 100문장에서 잘못 끊긴 수. 분리 오류가 다른 짝으로 번지지 않음을 테스트로 고정 |
| 노이즈 탐지 | 직접 만든 노이즈 문단 20개에서 제거 정확도와 잘못 지운 줄 수 |
| **유용성 (소규모)** | 수강생 5~8명이 같은 초록 2편을 각각 도구 없이 / 도구와 함께 읽는다(순서 교차). 이해 문제 3개 정답 수, 소요 시간, 짧은 설문 3문항을 받는다. **"소규모, 통계적 일반화 불가"를 명시**한다 |

검수는 규칙을 만든 시점과 다른 시점에 하고, 규칙 조정용과 보고용 자료를 나눈다. 목표에 못 미치면 못 미친 대로 보고한다.

## 13. AI 도구를 쓰는 방식

| 쓰는 곳 | 도구 | 사람이 확인하는 것 |
|---|---|---|
| 기획·문서 초안, 코드 작성 보조 | Claude Code (Anthropic) | 모든 결정과 컨펌은 이의상. 실제로 실행한 테스트 결과만 보고 |

| 학술 어휘 뜻 초안 (P1) | AI 초안 | 사람이 검수하고 출처를 명시 |

**정규식 규칙의 판단 근거는 사람이 설명할 수 있어야 한다.** AI가 만든 패턴도 테스트와 검수를 통과해야 채택한다.
