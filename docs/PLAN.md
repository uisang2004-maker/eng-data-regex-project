## 01. 먼저 합의할 한 장

**제품의 중심은 "대신 읽어 주기"가 아니라 "읽는 법 보여 주기"다.** 원문은 그대로 두고, 번역은 옆에서 돕고, 정규식은 읽어야 할 곳과 조심할 곳을 표시한다. 요약은 만들지 않는다.

| 이번에 확정하는 방향 | 실제로 보여줄 경험 |
|---|---|
| 대상: **영어 논문을 처음 읽는 학부생** | 과제로 받은 논문을 붙여 넣으면 첫 화면에서 바로 결과가 나온다. 로그인, 요금, 설치가 없다 |
| **영어·한국어 문장 단위 나란히 보기** | 영어 한 문장과 한국어 한 문장이 짝지어 보인다. 약어, 인용, 수치는 번역에서 망가지지 않는다 |
| **정규식이 번역 앞뒤를 책임짐** | 문장 분리 → 보호 마스킹 → DeepL 번역 → 복원·후처리. "마스킹 끄기"와 비교해 차이를 보여 준다 |
| 뼈대 문장과 추천 읽기 순서 | 문제·방법·결과·한계 문장이 카드로 모이고 "방법 → 결과 → 한계 순으로 읽기"를 안내한다 |
| 약어 → 풀네임 | 8쪽의 `RLHF`에 마우스를 올리면 1쪽에서 정의한 풀네임이 보인다 |
| 추측·확신 표시와 학습 팁 | `may indicate`는 추측, `we demonstrate`는 확신으로 칠한다. "단정하지 말고 인용하세요" 같은 팁을 붙인다 |
| 학술 어휘와 한국어 뜻 | `empirical`, `robust` 같은 학술 단어에 뜻을 붙인다. `-s/-ed/-ing` 변형도 regex로 잡는다 |
| **모든 표시에 근거 규칙** | 하이라이트마다 "규칙 HEDGE"처럼 어떤 패턴이 잡았는지 보인다. 규칙 목록 화면도 있다 |

**핵심 시연:** 과제 논문 한 단락을 붙여 넣는다 → 영한 나란히 보기와 색칠된 원문이 뜬다 → 뼈대 카드를 보고 "결과 문장"부터 읽는다 → 약어와 추측 표현의 툴팁에서 근거 규칙을 확인한다 → "마스킹 끄기"를 누르면 `BERT`·`[3, 5]`가 번역에서 망가지는 장면과 비교한다.

**현재 확보 상태 (2026-11-03 로컬 실행 기준):**
- arXiv cs.CL 초록 300건(연도 6개 × 50건, CC0, 저자 필드 제외)
- 이 샘플에서 초록 1편당 약어 정의 수: 2012년 0.22 → 2025년 1.04
- 정의 없이 쓰인 약어: 0.70 → 2.50
- 마스킹 왕복: 2,010문장 불일치 0
- DeepL 실제 번역: 예시문 9문장, 보호 토큰 13/13 보존

샘플은 각 연도 말에 제출된 최신 50건이라 **대표성이 없으며, 추세는 참고용**이다. 평가용 라벨과 pytest는 아직 없다.

**한 줄 차별화:** **AI가 대신 읽어 주는 대신, 정규식이 읽는 길을 보여 주는 논문 도우미.** 번역은 외부 엔진이 맡고, 무엇을 어떻게 읽을지는 근거가 보이는 규칙이 맡는다.

## 02. 해결할 문제와 기존 논문 AI의 가치

학생이 영어 논문을 어려워하는 이유는 용어만이 아니다.
- 약어·전문어
- 요점 찾기
- 주장 강도 판단
- 긴 문장 구조
- 배경지식과 참조 왕복

이 다섯 가지가 겹친다. 연구로도 과학 논문의 약어 비율 증가[R01]와 가독성 하락[R02]이 보고되었다.

기존 논문 AI는 이미 좋은 기능을 갖고 있다. 다만 **연구자·석박사 중심으로 발전했고, 판단 근거가 보이지 않는다.** 이유는 시장 구조를 보고 우리가 추론한 것이다.
- 지불 주체가 연구실과 기관이다
- 연구자는 사용 빈도가 높다
- 가끔 쓰는 사람은 범용 챗봇이 흡수한다
- 비전문가에게 틀린 요약을 줄 때의 책임 부담이 크다

| 기존 자산·관찰 | 우리가 바꿀 전달 방식 |
|---|---|
| Semantic Reader: Goal/Method/Result 하이라이트, 용어 정의 툴팁[R03][R04][R05] | 같은 방향의 표시를 **regex 규칙**으로 하고, 하이라이트마다 근거 규칙을 보여 준다. 분야 제한 없이 붙여 넣은 텍스트에 바로 적용한다 |
| SciSpace·Explainpaper: 드래그하면 LLM이 쉬운 말로 설명[R06] | 설명을 생성하지 않는다. 원문과 번역을 나란히 두고 **학생이 직접 판단**하게 한다 |
| scite: 다른 논문이 이 주장을 지지·반박했는지 | 바깥 인용 대신 **논문 안의 추측·확신 표현**을 칠한다. 조사 범위에서 일반 서비스로는 찾지 못했다 |
| 범용 챗봇 요약 | 요약은 틀려도 티가 나지 않는다. 우리는 원문을 지우지 않는다 |

**차별화의 핵심은 근거의 투명성과 대상이다.** "붙여 넣기 → 문장 분리 → 보호 번역 → 규칙 표시 → 근거 확인"이 이어지고, 그 대상이 기존 시장이 소홀히 한 학부생이라는 점이 핵심이다.

**검증할 변화:**
- 약어 풀네임과 추측 표현을 직접 라벨링한 기준으로 맞히는가
- 번역 후 약어·인용·수치가 100% 보존되는가
- `may be applied`처럼 추측이 아닌 경우를 잘못 칠하지 않는가

학생 이해도나 시간 절감은 이번 범위에서 측정하지 않는다.

## 03. 붙여 넣으면 화면 뒤에서 무엇이 움직일까

아래는 **직접 작성한 예시문**을 기준으로 한 설명이다. 실제 논문이 아니다.

| 순서 | 화면 뒤에서 일어나는 일 | 발표자가 설명할 말 |
|---|---|---|
| 1 | PDF 복사 잔재 정리: `termi-\nnology` → `terminology`, 줄바꿈 → 공백 | "PDF에서 복사하면 단어가 끊겨요. 정규식으로 먼저 이어 붙여요." |
| 2 | 문장 분리. `e.g.`, `et al.`, `Fig. 3`의 마침표는 문장 끝으로 보지 않음 | "영어 한 문장과 한국어 한 문장을 짝지으려면 문장을 정확히 나눠야 해요." |
| 3 | 약어 정의 탐색: `Natural Language Processing (NLP)` → 첫 글자 맞춤으로 풀네임 확정 | "괄호 안 대문자를 찾고, 앞 단어 첫 글자와 맞춰요." |
| 4 | 보호 마스킹: 약어·인용·참조·수치를 `<x>…</x>`로 감쌈 | "번역기가 `BERT`나 `[3, 5]`를 건드리지 못하게 포장해요." |
| 5 | DeepL 번역(`ignore_tags=x`), 결과 캐시 | "포장된 부분은 번역하지 않고 그대로 돌려줘요." |
| 6 | 복원·후처리: `<x>` 제거, "제Section" → "Section" | "번역기가 붙인 군더더기도 정규식으로 지워요." |
| 7 | 뼈대·추측/확신·학술 어휘 표시를 영어와 한국어 양쪽에 반영 | "영어에서 '결과 문장'이면 짝지어진 한국어 문장도 '결과 문장'이에요." |

**번역은 문장을 옮기고, 정규식은 무엇을 어떻게 읽을지 알려 준다.** 이 역할 분담을 발표의 첫 메시지로 삼는다.

## 04. 처음 읽는 학생에게는 정보량보다 읽는 순서가 중요하다

**구체적인 화면 배치, 색, 디자인은 이의상 님의 지시를 받아 정한다.** 이 절은 어떤 디자인이든 지켜야 할 기능 원칙만 적는다.

- 원문을 지우거나 바꾸지 않는다. 번역과 표시는 원문 **옆이나 위에** 둔다
- 영어 문장과 한국어 문장은 같은 순서·같은 단위로 짝지어 보인다
- 색만으로 의미를 전달하지 않는다. "추측", "결과" 같은 텍스트 표시를 함께 둔다
- 모든 하이라이트에서 근거 규칙을 확인할 수 있다
- 외부 번역 서비스로 텍스트가 전송된다는 사실을 화면에 안내한다("개인정보를 넣지 마세요")
- 첫 화면에서 **입력 → regex 표시 → 결과**가 바로 보인다(과제 조건)

## 05. 코드를 몰라도 이해하는 서비스 구조

| 쉬운 이름 | 기술 이름 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 화면 | Streamlit (`app.py`) | 입력, 영한 나란히 보기, 색칠, 카드, 그래프 표시 | API 키 보관, 사용자 텍스트 저장 |
| 규칙 모음 | `src/patterns.py` | 모든 정규식과 설명(잡는 것, 예시, 일부러 놓치는 경우) | 규칙 밖의 판단 |
| 정리 담당 | `src/clean.py` | 하이픈·공백 정리, 문장 분리 | 내용 수정, 요약 |
| 추출 담당 | `src/extract.py` | 약어·뼈대·추측/확신·학술 어휘·참조 찾기 | 논문 내용의 사실성 보증 |
| 번역 포장 담당 | `src/translate.py` | 보호 마스킹, DeepL 호출, 복원·후처리, 캐시 | 번역 품질 보증, 키를 코드에 저장 |
| 문장 옮기기 | DeepL API Free | 영어 → 한국어 문장 번역 | 약어 해석, 독해 표시 |
| 수집 담당 | `src/collect.py` | arXiv API로 초록 수집(3초 간격) | 저자 정보 수집, 본문 무단 수집 |
| 통계 담당 | `src/analyze.py` | 연도별 지표, 평가 지표 계산 | 대표성 없는 샘플을 전체 추세로 주장 |
| 검사 담당 | `tests/` (pytest) | 패턴별 양성·음성, 마스킹 왕복 테스트 | — |

**정규식은 규칙, 번역기는 문장 옮기기, 판단은 학생.** 이 세 역할을 섞지 않는 것이 설계와 발표의 출발점이다.

## 06. 정규식이 결과의 핵심 원인이 되는 곳

과제의 핵심은 regex로 영어 텍스트를 처리하는 것이다. 아래 표시는 **regex를 빼면 아무것도 남지 않는다.** 예시는 2026-11-03 프로토타입에서 실행해 확인했다.

| 범주 | 패턴 요약 | 확인한 예 | 일부러 놓치는 경우 |
|---|---|---|---|
| 전처리 | `(?<=[a-z])-[ \t]*\n[ \t]*(?=[a-z])` → 제거 | `termi-\nnology` → `terminology` | `state-of-\nthe-art`처럼 원래 하이픈이 있던 단어 |
| 문장 분리 | `(?<=[.!?])\s+(?=[A-Z(\["'])` + 예외 약어 목록 | `e.g.`, `et al.`, `Fig.`에서 끊지 않음 | 예외 목록에 없는 약어 |
| 약어 정의 | `\(\s*(?P<abbr>(?=(?:[^A-Z)]*[A-Z]){2})[A-Za-z][A-Za-z0-9-]{1,11})\s*\)` + 첫 글자 맞춤 | `Long Short-Term Memory (LSTM)`, `Reinforcement Learning from Human Feedback (RLHF)` | 첫 글자 규칙을 따르지 않는 약어 |
| 추측(hedge) | `\b(?:may\|might\|could)\b(?!\s+be\s+(?:used\|applied\|…)\b)\|…suggests?…` | `may indicate` O / `may be applied` X | 문맥에 따라 뜻이 달라지는 표현 |
| 확신(booster) | `demonstrat(?:e\|es\|ed\|ing)\|significantly\|state[- ]of[- ]the[- ]art…` | `We demonstrate`, `significantly` | 통계적 "significant"와 강조의 구분 |
| 뼈대 문장 | `in this (?:paper\|work),? we\|we propose…`, `results? (?:show\|indicate)…` 등 4범주 | 방법·결과·문제·한계 문장 | 신호 문구 없이 쓴 문장 |
| 참조 | `\[\d+(?:\s*[,–-]\s*\d+)*\]`, `\(… et al\.,? \d{4}\)`, `Fig\.?\s*\d+` | `[3, 5]`, `(Smith et al., 2021)`, `Table 2` | 각주형 인용 |
| 번역 보호 | 위 참조·약어·수치 패턴 → `<x>` 감싸기 | 13/13 보존 | URL 안의 특수문자 일부 |
| 번역 후처리 | `제\s?(?=(?:Sec(?:tion)?\|Table\|Fig…)\b)` → 제거 | `(제Section 5.1)` → `(Section 5.1)` | 다른 형태의 조사 결합 |
| 학술 어휘 (예정) | `\b(?:analy[sz]e\|empiric\w*\|robust\w*…)\b` 목록 × 굴절형 | — (미구현) | 불규칙 변화형 |

## 07. 번역은 DeepL, 보호는 정규식

**번역 엔진은 DeepL API Free로 결정했다(2026-11-03, 이의상 선택).**

| 확인한 사항 | 근거 |
|---|---|
| 무료 등급 월 500,000자 | 공식 문서[R09] |
| Free 엔드포인트 `api-free.deepl.com`, Free 키는 끝이 `:fx`, `DeepL-Auth-Key` 헤더 | 공식 문서[R08] |
| `tag_handling=xml` + `ignore_tags=x`이면 `<x>` 안의 텍스트를 번역하지 않음 | 공식 문서[R10] |
| 무료 등급에서 보낸 텍스트의 보관·활용 여부 | **미확인**. 확인 전까지 화면에 전송 안내를 한다 |

**실측 (2026-11-03):**
- 예시문 9문장(1,061자) 번역에서 보호 토큰 13/13을 보존했다
- 숫자 뒤 공백 문제("300 편")와 "제Section"은 regex를 수정해 해결했다

**남은 문제:**
- 문장을 따로 번역해서 "~습니다"와 "~한다"가 섞인다
- Phase 3에서 문단 단위 전송 후 재분리와 어미 정규화를 비교해 고른다

**운영 원칙:**
- 키는 `.env`에만 둔다(커밋 금지)
- 시연 예시는 캐시해서 인터넷 없이도 동작하게 한다
- 무료 한도를 넘는 호출이나 유료 전환은 승인 없이 하지 않는다

## 09. 데이터는 합법적인 것만, 샘플은 샘플답게

| 데이터 | 용도 | 출처·권리 | 원칙 |
|---|---|---|---|
| 사용자가 붙여 넣는 텍스트 | 시연 | 사용자 본인 | 저장하지 않는다. 번역 시 외부 전송을 안내한다 |
| arXiv 초록 | 규칙 개발·평가·분석 | arXiv API, 메타데이터 CC0 1.0[R07] | 3초에 1회 요청, 저자 필드 제외. 300건에서 1,000~3,000건으로 확대 예정 |
| 직접 작성한 예시문 | 기능 시연 | 팀 작성 | 화면에 "직접 작성, 실제 논문 아님"을 표시한다 |
| 학술 어휘 목록 | F6 | 공개 목록(라이선스 **미확인**) 또는 우리 샘플 빈도로 추출 | 라이선스가 확인되지 않으면 직접 추출한 목록을 쓴다 |
| 어휘 한국어 뜻 300~500개 | F6 | AI 초안 + 사람 검수 | AI 사용 사실을 README에 명시한다 |
| 번역 캐시 | 오프라인 시연 | 예시문의 DeepL 결과 | 실제 논문 원문은 캐시를 커밋하지 않는다 |

샘플 결과를 전체 학계의 추세로 말하지 않는다. 발표에서는 "소량 샘플에서도 선행 연구[R01]와 같은 방향"이라고만 말한다.

## 10. 4주 안에 연결하는 순서

개발의 기준은 완제품이 아니라 **처음부터 끝까지 끊김 없는 3분 시연**이다. 기능을 늘리기 전에 규칙과 테스트를 먼저 고정한다.

| 시기 | 할 일 | 눈으로 확인할 결과 |
|---|---|---|
| 1주차 11/03–11/09 (Phase 2) | 계획서 확정, 번역 엔진 결정·키 발급(완료), **UI 지시 반영 프로토타입 2차**(영한 나란히 보기 연결) | 붙여 넣은 문단이 영한 나란히 + 색칠로 보임 → **컨펌** |
| 2주차 11/10–11/16 (Phase 3) | `src/` 모듈화, `patterns.py` 이전, pytest(경계 사례: 축약형·하이픈·대소문자·둥근 따옴표), 초록 수집 확대, 학술 어휘 목록 확정 | `py -I -m pytest` 통과, README의 재현 명령으로 데이터 재생성 |

**마감 게이트:** 정확한 제출일·발표일이 확인되면 다시 계산한다. 늦어지면 P1부터 줄이고, P0 중에서는 F8, F6 순으로 축소한다.

**범위 기준:** P0는 영한 나란히 보기, 뼈대·약어·추측/확신, 근거 규칙 표시, 테스트다. 배포는 외부 공개 행위라서 **이의상 님의 승인 후**에만 한다.

## 11. 정확도는 설계가 아니라 결과로 입증한다

아래 숫자는 **사전 목표**이며 현재 실적이 아니다.

| 평가 | 계획과 완료 기준 |
|---|---|
| 약어 | 초록 50편의 약어 정의를 사람이 라벨링. 풀네임 정밀도 0.9 이상 목표, 재현율 함께 보고 |
| 추측·확신 | 50편의 hedge/booster를 라벨링. 정밀도 0.8 이상 목표. `may be applied`류 오탐 사례를 따로 집계 |
| 뼈대 문장 | 4범주별 정밀도·재현율 보고. 목표치는 첫 측정 후 정함 |
| 번역 보호 | 약어·인용·수치 보존율 100% 목표. 마스킹 끄기와 비교한 훼손 사례 수 |
| 문장 분리 | 예외 약어(`e.g.`, `et al.`, `Fig.`)가 들어간 문장 100개에서 잘못 끊긴 수 |
| 테스트 | 패턴마다 양성·음성 사례, 경계 사례 포함. CI 없이도 로컬 pytest로 재현 |

라벨링은 규칙을 만든 사람과 다른 시점에 하고, 규칙 조정용 자료와 최종 보고용 자료를 나눈다. 목표에 못 미치면 못 미친 대로 보고한다. 50편 결과를 모든 분야의 정확도로 일반화하지 않는다.

## 12. 동료 평가자에게 설명할 것

| 평가 관점 (팀 판단 기준) | 직접 보여줄 증거 |
|---|---|
| regex 중심성 | 규칙 목록 화면, 하이라이트의 근거 툴팁, 마스킹 on/off 비교 |
| 시연 임팩트 | 평가자 본인의 과제 논문을 즉석에서 붙여 넣기 |
| 데이터 실현성 | CC0 arXiv 초록, 직접 작성한 예시문, 사용자 입력만 사용 |
| 차별성 | 연구자용 AI와 달리 학부생 대상이고 근거가 보이는 규칙 |
| 범위 적합성 | P0만으로 완결되는 3분 시나리오, 오프라인 캐시 |

위 다섯 항목은 수업 공식 배점이 아니라 **우리 팀의 아이디어 판단 기준**이다.

**마지막에 전달할 한 문장:** "번역기는 문장을 옮기고, 정규식은 읽는 길을 보여 줍니다. 그래서 처음 읽는 논문도 원문을 놓치지 않고 읽을 수 있습니다."

## 13. AI 도구를 쓰는 방식

과제는 AI 도구 사용을 허용한다. 우리는 사용 내역을 README에 정직하게 적는다.

| 쓰는 곳 | 도구 | 사람이 확인하는 것 |
|---|---|---|
| 기획·문서 초안, 코드 작성 보조 | Claude Code (Anthropic) | 모든 결정과 컨펌은 이의상. 테스트를 실제로 실행한 결과만 보고 |
| 번역 | DeepL API Free | 번역 품질 자체는 보증하지 않으며, 보호 토큰 보존을 테스트로 확인 |
| 학술 어휘 뜻 초안 | AI 초안 | 사람이 검수하고 출처를 명시 |

**정규식 규칙의 판단 근거는 사람이 설명할 수 있어야 한다.** AI가 만든 패턴도 테스트와 라벨 평가를 통과해야 채택한다.

| 위험 | 대응 |
