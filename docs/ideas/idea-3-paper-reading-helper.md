# 아이디어 3. 논문 독해 도우미 (Paper Reading Helper)

> 개정 이력: 2026-11-03 「논문 약어 X-ray」 → 「논문 독해 도우미」로 확장했다. 사용자 피드백("논문 읽을 때 어려웠던 경험이 와닿는다")을 반영했다.

## 한 줄 요약

영어 논문 텍스트(초록에서 본문까지)를 붙여 넣으면, 정규표현식이 논문 읽기를 어렵게 하는 다섯 가지를 표시한다. ① 약어 → 풀네임 툴팁 ② 문제·방법·결과·한계 "뼈대 문장" ③ 추측(hedge)과 확신(booster) 색 구분 ④ 문장 난이도 ⑤ 인용·그림·수식 참조 목록. 하이라이트마다 **어떤 규칙이 잡았는지** 보여 준다는 점이 AI 블랙박스 서비스와 다르다.

## 왜 이 주제인가

- 논문을 읽기 어려운 이유: 약어·전문어, 요점 찾기, 주장 강도 판단, 긴 문장 구조, 배경지식·참조 왕복
- 연구 근거
  - Barnett & Doubleday(2020, eLife): 1950년 이후 과학 논문에서 약어 비율이 3배 넘게 늘었다
  - Plavén-Sigray 외(2017, eLife): 생의학 초록의 가독성이 꾸준히 떨어졌다
- 비슷한 서비스(Semantic Reader, SciSpace, Explainpaper, scite)는 모두 AI 모델 기반이라 근거가 보이지 않는다. Semantic Reader의 하이라이트는 arXiv 컴퓨터과학 논문에만 적용된다(2023-10 기준). 주장 강도를 색칠하는 일반 서비스는 조사 범위에서 찾지 못했다

## 데이터와 출처

| 구분 | 텍스트 | 출처·라이선스 |
|---|---|---|
| ① 독해 도구 | 사용자가 붙여 넣는 아무 텍스트 | 수집·저장하지 않는다 |
| ② 분석 탭 | arXiv 초록 (프로토타입은 cs.CL 연도별 소량) | arXiv API. 메타데이터 CC0 1.0. 3초에 1회 요청. 저자 필드는 수집하지 않는다 |
| ③ 선택 | 재사용 허용 라이선스(CC BY 등) 논문 본문 수십 편 | 논문별 라이선스 확인 필요(**미확인**) |

## 핵심 regex

| 범주 | 패턴 예시 | 잡아내는 것 |
|---|---|---|
| 전처리 | `(\w)-\n(\w)` → `\1\2` | PDF에서 복사할 때 생기는 줄바꿈 하이픈 |
| 약어 정의 | `\((?P<abbr>[A-Z][A-Za-z]*[A-Z]s?)\)` + 첫 글자 맞춤 | `Natural Language Processing (NLP)` |
| 뼈대 문장 | `\b(?:in this (?:paper\|work\|study)\|we (?:propose\|present\|introduce))\b` 등 | 문제·방법·결과·한계 문장 |
| 추측 | `\b(?:may\|might\|could\|suggests?\|likely\|possibly)\b`, 단 `may be (?:used\|applied)` 류는 제외 | hedge |
| 확신 | `\b(?:demonstrate[sd]?\|clearly\|significantly\|prove[sn]?\|outperform\w*)\b` | booster |
| 난이도 | `\b(?:is\|are\|was\|were\|be\|been\|being)\s+\w+ed\b`, `\b\w+(?:tion\|ment\|ness\|ity)s?\b` | 수동태, 명사화 |
| 참조 | `\[\d+(?:[,–-]\s*\d+)*\]`, `\([A-Z][a-z]+ et al\.,? \d{4}\)`, `\b(?:Fig(?:ure)?\|Table\|Eq)\.?\s*\(?\d+\)?` | 인용, 그림·표·수식 참조 |

## 파이프라인

collect(arXiv API) → clean(하이픈·공백·LaTeX 정리) → extract(범주별 패턴) → analyze(연도별 초록당 약어 수, 100단어당 hedge·booster 수, 평균 문장 길이) → visualize(하이라이트 화면, 뼈대 카드, 추이 그래프)

## 결과 화면 묘사

왼쪽에 텍스트를 넣으면 오른쪽에 색칠된 본문이 나온다. 약어 위에 마우스를 올리면 풀네임이 보이고, 각 하이라이트에 매칭된 규칙 이름이 툴팁으로 뜬다. 위쪽에는 "이 글의 뼈대" 카드 4장(문제/방법/결과/한계)이 있다. 분석 탭에는 연도별 "초록 1편당 약어 정의 수"와 "100단어당 hedge/booster" 그래프가 있다.

## 판단 기준 점수 (개정)

| 기준 | 점수 | 근거 |
|---|---|---|
| regex 중심성 | 5 | 다섯 기능이 모두 패턴 매칭이다. 약어 맞춤만 일부 Python 로직이 들어간다 |
| 시연 임팩트 | 4 | 수강생 모두 영어 논문을 읽어 봤다. 자기 과제 논문을 붙여 넣어 볼 수 있다. 다만 결과의 정확도가 체감을 좌우한다 |
| 데이터 실현성 | 5 | 사용자 입력과 CC0 초록이라 법적 위험이 낮다 |
| 차별성 | 4 | "규칙이 보이는" 독해 도우미라는 점이 기존 AI 서비스와 다르다 |
| 범위 적합성 | 4 | 범주가 다섯 개라 넓다. 4번(난이도)과 5번(참조)은 선택 기능으로 둘 수 있다 |
| **합계** | **22** | |

## 예상 위험

- hedge의 애매함(`may be applied`): 제외 패턴과 테스트로 대응하고, 직접 라벨링한 정밀도를 공개한다
- 분야별 관습 차이: 1차 범위를 CS·AI로 한정한다
- 배경지식 부족은 해결하지 못한다. 한계에 적는다
