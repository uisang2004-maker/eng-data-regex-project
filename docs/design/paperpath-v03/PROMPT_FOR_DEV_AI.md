# 개발 AI에게 전달할 작업 지시문

아래 작업 지시와 같은 폴더의 `DEVELOPMENT_HANDOFF.md`를 기준으로 실제 PaperPath 앱을 구현해 주세요.

## 역할

당신은 Streamlit 기반 Python 애플리케이션을 구현하는 개발 에이전트입니다. 이 작업은 새 제품을 재기획하는 것이 아니라, 확정된 v03 UI를 실제 기능과 연결하는 개발입니다.

## 먼저 읽을 자료

1. `DEVELOPMENT_HANDOFF.md` 전체
2. `references/PLAN-4th-revision-2026-11-04.md` 전체
3. `references/paperpath-v03-approved.png`
4. `references/index-v03-visual-reference.html`

## 핵심 지시

- 첫 화면의 레이아웃, 색상, 글꼴 위계, 카드 스타일을 v03와 최대한 일치시켜 주세요.
- 기능 요구사항과 기술 구조는 2026-11-04 4차 기획서를 우선해 주세요.
- Streamlit을 유지하고, 기획서의 모듈 구조(`app.py`, `src/`, `tests/`)로 나눠 주세요.
- 먼저 P0 6개를 완성하고 pytest로 확인한 뒤에만 P1을 검토해 주세요.
- 정규식이 제품의 핵심입니다. LLM 생성 요약이나 자동 해설로 기능을 대체하지 마세요.
- 원문을 임의로 바꾸거나 원문에 없는 요약문을 만들지 마세요.
- 번역 API는 버튼 클릭 때만 호출하고, 비교 API는 별도 버튼을 눌렀을 때만 호출하세요.
- 사용자가 입력한 원문을 저장하지 말고, DeepL 전송 전에 안내해 주세요.
- API 키는 `.env`에서만 읽으세요. 키를 코드/로그/README 예시의 실값으로 쓰지 마세요.
- 임의의 Regex 입력 기능, PDF 업로드, 로그인/기록 저장, 생성형 설명 기능은 추가하지 마세요.

## 작업 순서

1. 기존 저장소/파일 구조를 확인하고 현재 구현 상태를 보고하세요. 파일이 이미 있다면 먼저 읽고 중복 구현을 피하세요.
2. UI 구조를 v03 캡처와 대조하고, 정적 목업의 하드코딩 텍스트를 실제 상태 기반 컴포넌트로 교체하세요.
3. 입력 및 텍스트 최소 전처리(P0-1)를 구현하세요.
4. 뼈대 문장 선택 및 이유/추정 라벨(P0-2)을 구현하세요.
5. 약어 탐지와 매칭(P0-3), 추측/확신/참조(P0-4)를 모듈화하세요.
6. 지연 실행 번역, 마스킹 비교, 캐시/오류/개수 안전장치(P0-5)를 구현하세요.
7. 읽기 전용 단계 보기와 준비된 규칙 on/off(P0-6)를 구현하세요.
8. 규칙 탐색/검증 결과 탭을 구현하고 목표·측정·한계를 구분하세요.
9. 1440×900과 모바일 뷰를 캡처해 v03와 비교하고, 잘림/겹침/대비/조작성을 수정하세요.
10. `py -I -m pytest` 및 직접 실행 점검을 실시하고, 실제 통과/실패 결과를 기록하세요.

## 반드시 보고할 결과

- 수정/생성한 파일 목록
- P0-1~P0-6 구현 상태표
- 테스트 명령과 실제 결과
- 1440×900 및 모바일 스크린샷 경로
- 아직 구현하지 못한 사항과 기획서에서 판단이 필요한 사항
- 실행 방법과 필요한 환경변수 이름(값은 절대 출력하지 말 것)

## 금지 사항

- 테스트하지 않은 기능을 완료했다고 말하지 마세요.
- 임의의 성능/정확도 수치를 만들지 마세요.
- DeepL 데이터 보관 여부를 확인 없이 단정하지 마세요.
- UI 재설계를 새로 제안하거나 v03 레이아웃을 임의로 바꾸지 마세요. 개선이 필요하면 먼저 현재 기준과 차이를 설명하고 별도 제안으로 분리하세요.
- P1 기능을 P0보다 먼저 구현하지 마세요.

**완료의 기준은 화려한 화면이 아니라 P0 6개가 끊김 없이 동작하고, 모든 강조의 근거를 설명할 수 있으며, 3분 시연을 안정적으로 수행하는 것입니다.**
